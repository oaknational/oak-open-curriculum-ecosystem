# Known issues

Transparency list (learned from govuk-frontend's public known-issues register): things a consumer may hit that are already understood. Don't re-diagnose these.

1. **`@import`-only stylesheets parse to zero rules for pages served inside this project.** `styles.css` is the entry point for EXTERNAL consumers; pages _within_ this project (plain HTML, DCs, cards) must link `colors_and_type.css`, `components.css`, `print.css` directly. Same applies to a brand's `brand-full.css` in DC contexts — link both brand parts directly.
2. **DOM-re-render screenshots misreport theme and form state.** html-to-image-style captures (including this workspace's preview captures) may ignore `color-scheme`/`light-dark()` flips and reset `<select>` displayed values. The page is right; the capture isn't. Verify themes in a real browser or via the contrast audit's computed numbers. **Do not over-trust this rule the other way:** a "narrow column" region render was blamed on this for several passes but was a real bug (see issue 8) — when a capture artifact is suspected, confirm with `getBoundingClientRect()` on the LIVE page, not just computed track sizes: tracks can be healthy while items collapse.
3. **Brand icon sets are a network dependency.** `whitelabel/creature/icons.css` loads Material Symbols Rounded from Google Fonts; `whitelabel/pds/icons.css` loads Bootstrap Icons from jsDelivr. Oak's own icon set is local (`assets/icons/`); a re-brand that must work offline should bundle its icons the same way.
4. **PDS v7 dark polarity is this project’s own.** GDS ships light-only, so the dark ramp (light-blue links #5694ca, brightened action-green plate #00b374 with ink text, dark-derived panel tints) is derived here on GDS hues, audit-checked; re-audit after touching it. PDS loads Public Sans from Google Fonts (same network dependency as issue 3). Brand history (v4 printed-record → v5/v7 GDS) lives in whitelabel/pds/BRAND.md.
5. **`--weight-light` is 400 in both proof brands.** Their fonts have no safe 300; a brand supplying its own face must check the 300 weight renders legibly or re-point the token.
6. **Keep a template's `<template id="__bundler_thumbnail">`.** It looks inert (it is, at runtime) but the standalone-HTML bundler requires it; deleting it breaks the export.
7. **A composition map must place every region.** `grid-template-areas` is all-or-nothing: one misspelled or missing region name invalidates the whole template (the custom property substitution then collapses the layout). When a brand map looks "ignored", diff its area names against the region list in components.css first. Also check its scope: maps live under `[data-page="<type>"]`, never `:root` — an unscoped map from one page shape silently corrupts every other page, and a scoped map does nothing if the page forgot its `data-page` attribute. And check the DOM: the region→area assignments are direct-child (`>`) selectors by design — a region whose computed `grid-area` is `auto` despite a correct map is usually not a direct child of `.oak-main`/`.oak-canvas` any more (a stray close tag is enough; the parser can resolve it against `div.oak-canvas` and silently reparent everything after it to `<body>`).
8. **Never put inline-size containment on a region.** `.oak-region` is `container-name:region` only. `container-type:inline-size` zeroes an element's intrinsic inline size; on a grid item that doesn't stretch (any auto inline margin — `.oak-container` — or `justify-self` other than stretch) the region collapses to its padding. If a consumer wants `@container region (width…)` queries, the size containment belongs on a wrapper INSIDE the region, never on the grid item itself.
9. **`_ds_bundle.js` includes every compilable `.js` source in the project** — currently that means `integrations/revealjs/vendor/reveal.js` (~115 KB) and `preview/tweaks-panel.js` ride along in the compiled bundle consuming projects load. Harmless at runtime (they self-contain), but real bytes; if bundle weight matters, relocating the reveal.js vendor copy outside the project (CDN link in the sample deck) is the known remedy. (Kept deliberately July 19: the consuming repo will take reveal.js as a real dependency.)
10. **Keep `oak-icons.css` at the project root, beside `components.css`.** A `url()` stored in a custom property may resolve against the DECLARING stylesheet or the CONSUMING stylesheet depending on engine (this workspace's webview resolves against the consumer). With both sheets sharing one base, both rules give the same answer. Moving the icon map into a subfolder re-breaks Oak's mask icons with silent 404s (hit July 19). The same applies to any brand stylesheet declaring relative `--ic-*` URLs — counter-brands avoid it by using absolute CDN URLs.
11. **The compiler compiles ANY capitalised-export `.tsx`/`.jsx` anywhere in the project — including `docs/` — into `_ds_bundle.js` and onto the public namespace.** A doc-only code sample must use a non-compiled extension (the convention here: `.tsx.txt`, e.g. `docs/nextjs-theme-switcher.tsx.txt`); consumers rename on copy. Found 1.6.6 when the theme-switcher sample shipped as a phantom 5th component.

12. **RESOLVED 2026-07-20** — `colors_and_type.css` formerly made one runtime network call (a fonts.googleapis.com `@import` for Roboto Mono, code contexts only), which every canonical-chain consumer inherited (privacy/offline/CSP posture). Cured by the standing better cure this entry named: Roboto Mono now ships as the local variable font `fonts/RobotoMono-VariableFont_wght.ttf` (`@font-face`, weights 100–700, same pattern as Lexend). Its licence is SIL OFL 1.1 — this entry's earlier "Apache-2.0" note was stale (Roboto Mono was relicensed); the verbatim notice + OFL text ship beside the font (`fonts/RobotoMono-OFL.txt`, likewise `fonts/Lexend-OFL.txt` for Lexend), per OFL condition 2. Side effect worth knowing: the variable font supplies a true 300 weight, so `--weight-light` code text renders genuinely light instead of snapping to the 400 the old three-weight import provided. Consumers on pre-resolution versions still make the network call. Declared 2026-07-19 (repo integration, PR #411); resolved in the consuming repo 2026-07-20.

13. **Dark body links miss AA on lemon bands (`surface.decorative-5`) by a hair.** The dark link ramp (lavender50/30/20, 2026-07-23) holds ≥4.5:1 on the dark canvas and on decorative bands 1, 2, 3, 4 and 6 — those pairings are pinned in `dtcg/contrast-pairings.json` and machine-checked at every build. Dark-lemon (`#645811`) is the one base it cannot clear: 4.48:1, gate-measured (the 2026-07-23 studio review's "≥5.3:1 on every dark decorative base" over-claimed here). Don't put body links inside a lemon band in dark; if a page genuinely needs one, it must re-point `--text-link` in that band's scope and re-audit.

14. **`:root`-declared aliases freeze under SUBTREE high-contrast / colour-safe theming.** A custom property declared once at `:root` with a bare `var()` (no `light-dark()`) substitutes at computed-value time on `:root` — so inside a subtree `[data-theme='high-contrast']`/`[data-theme='colour-safe']` scope, the theme block's re-declaration of the alias's _target_ does not reach the alias: it renders the inherited root-resolved value. Affects `--border-accent`, `--bg-selected`, and the whole Oak-dialect alias block (`--surface-mint` …); `--surface-decorative-6-soft` and `--surface-amber-soft` (both new 2026-07-23) were cured at landing by per-theme re-declaration. Root-level theming (the common case, `data-theme` on `<html>`) is unaffected; dark/system subtrees are also unaffected (`light-dark()` streams evaluate per element). The general rule is now recorded in DECISIONS "A composed token is substituted where it is declared" (2026-07-26): a custom property that composes other custom properties must be re-declared wherever its inputs are overridden. What stays open here is only the alias-block breadth question — re-declare every dialect alias per theme block, or narrow the subtree contract for HC/colour-safe; until ruled, avoid dialect aliases inside HC/colour-safe _subtrees_ (use the `--surface-decorative-N` roles directly; they re-declare correctly).

# DECISIONS — the journey, intent and meaning behind this design system

This file travels with every export. It records not just what the system is, but why — the decisions, the rejected alternatives, the lessons paid for. `README.md` describes the system; `HANDOFF.md` carries in-flight state; this is the durable record. Format: **Decision — rationale — consequences.**

## Founding intent

Oak National Academy's mission frames every choice: all learners have a fundamental right to access education. So **accessibility is a condition, not a feature** — WCAG 2.2 AA is the floor in every theme and every re-brand, AAA the aspiration. And because teaching happens on projectors, paper, Word documents and phones, **multi-medium excellence is first-class**, not an afterthought of the web build. The system is also **white-label-ready by design**: the open-curriculum ecosystem invites others to build on Oak's work under their own brand, so the brand had to be an override surface, not a hardcoded skin.

## Architecture

**Three strict token tiers.** Tier 1 primitives (`--oak-*` palette + scales, literals live ONLY here) → tier 2 semantic roles (`--text-*`, `--bg-*`, `--surface-*`…) → tier 3 component tokens (`--btn-*`, `--input-*`…). The `.oak-*` class library and the compiled React components consume the same tier-3 tokens, so class/component drift is impossible by construction. Rationale: every medium and every re-brand plugs in at a tier boundary. Consequence: no raw values at point of use anywhere; deliberate exceptions are hex labels in colour specimens, tweak swatch data, and fixed brand-art SVG fills.

**`light-dark()` over duplicated theme scopes.** Each role is composed once — `--text-primary: light-dark(black, white)` — instead of maintaining parallel `:root` and `[data-theme=dark]` blocks. Rationale: one declaration per role means dark can never silently miss a token. Consequence: theme switching is one `color-scheme` flip; `print.css` prints dark pages light with a single flip too. High-contrast and colour-safe remain explicit `[data-theme]` scopes because they change *values*, not just polarity.

**Four themes, not two.** Light, dark, high-contrast (near-monochrome, true-black ink, no decorative fills), colour-safe (state colours re-picked for colour-vision deficiency). Rationale: "state is never colour alone" is only testable if a theme exists where colour carries nothing. With no stored choice, `prefers-contrast: more` auto-maps to high-contrast (live-updating; explicit choice wins) — honouring OS preferences is part of access.

**Accent cascade.** `--color-accent` (lemon) feeds shadows, focus rings, selection, markers. Re-pointing one token re-brands the signature interactions. Lemon stays lemon in dark mode — it's the signature.

**Dialect aliases.** Brand-flavoured names (`--surface-mint`) are pure `var()` refs to canonical roles (`--surface-decorative-1`). Writers get the brand vocabulary; the theme engine only ever sees canonical roles.

## Accessibility decisions

**Double focus ring** (lemon 2px + contrast 5px halo) on `:focus-visible`, paired with a *transparent* outline so Windows forced-colors draws its own. Never removed or weakened; deliberately exceeds AA.
**Targets:** md 48px (AAA), floor 44px; `--sm` 36px exists only for dense desktop UI.
**Text on pastels:** always `--text-primary` at weight 400+, never white, never 300 below 18px — pastel fills fail contrast with white text, a classic pretty-but-inaccessible trap.
**Quiet motion:** 120/200ms only, verbs (`--motion-enter/exit/emphasis`) not values at point of use; everything collapses under `prefers-reduced-motion`. No bounces, no parallax — classrooms include vestibular-sensitive learners.
**Motion is an axis, not a theme** (decided July 2026): reduced motion composes with every colour theme, so it lives on its own attribute. Default follows the OS; `data-motion="reduced"|"full"` is the explicit override, persisted by `oakTheme.motion` — because pupils and teachers on school-managed devices often cannot change OS settings, the knob must exist in-product. Collapse happens at token level (the motion tokens themselves zero out), so every consumer stills without maintaining selector lists. `"full"` is permissible only because nothing louder than 120/200ms fades exists to re-enable.
**The charter split** (`preview/a11y-charter.html`): what the *system* guarantees vs what *every build* must still do. Rationale: a design system can't make an app accessible; pretending otherwise breeds complacency.
**Performance budgets are access** — principle recorded in the charter, tokens deliberately NOT shipped: a budget is app-scoped (a lesson player and a marketing page differ), so consuming apps define e.g. `--budget-first-interaction`.

## White-label contract

`brand.css` is the override surface, split into Part A "minimal viable brand" (~14 tokens: fonts, accent trio, decorative ramp — a credible re-brand in an afternoon) and Part B extended surface, with a hover-derivation recipe via `color-mix()`. **A11y is a condition of the contract**: focus, targets, motion, and state-not-colour-alone are OFF the override surface, and a re-brand is not done until `preview/contrast-audit.html` passes every theme. Rationale: the one thing a white-label must never trade away is access.

**The contract is proven, not asserted** (July 2026, `whitelabel/`): two deliberately opposite fictional counter-brands ship as working proofs — *Educate My Creature Too* (sweet-shop/fairground edtech: pill controls, plum ink, candy ramp, Nunito/Baloo 2, dark-first) and the *Office of Education* (the public service — currently v7, authentic GDS visual grammar in Public Sans; see BRAND.md there for the v4→v7 journey). Each ships Part A and full-contract stages separately (the stage toggle on the proof pages shows the delta), a geometric mark + wordmark, and the same markup as Oak throughout — only the brand CSS differs. The templates take `?brand=<slug>`. And the guardrails are stress-tested: `whitelabel/failing-example.css` is a deliberately broken re-brand (vanishing greys, pastel links, invisible focus halo) that the contrast audit's brand selector must flag — proving a bad re-brand cannot silently pass.

## Multi-medium decisions

**`print.css` ships in the cascade everywhere** (not a separate print build): one `color-scheme` flip, `print-color-adjust` on meaning-bearing fills, break rules. **SVG contract:** `currentColor` + `.oak-svg-*` token classes so the same markup themes, prints and re-brands; attribute hexes reserved for fixed brand art. **DOCX mapping:** Word can't consume CSS, so the ramp maps to named paragraph styles (documented in README) — an editable `.docx` is built with real Word styles, not exported pixels. **Display type scale** (`--font-size-11…14`, 64–96px) exists because projection is a first-class medium; slides keep a ≥24px floor and carry hierarchy in borders + fills to survive washed-out projectors.

**The signature is a brand choice, not a system constant** (July 2026, after the first white-label proofs looked "like Oak with a different accent"): the re-brand surface now includes the display face (`--font-display`/`--weight-display` — every heading class and template heading consumes them), heading tracking, the offset-shadow signature itself (`--shadow-accent*`, `--shadow-press` — documented recipes: Oak diagonal / straight-down drop / fully flat), geometry (`--radius-control/container`, `--border-solid-m`) and control density (`--control-pad-*`). Part A grew from ~14 to ~16 tokens (the display face joined it) because typography is the single biggest "different feel" knob. What stays off-surface is unchanged: focus ring, targets, motion behaviour, state-not-colour-alone.

**Authoring is first-class, not just consumption** (same session): the class library gained the lesson-content vocabulary, and (per user direction) the class names and labels match Oak's REAL lesson anatomy — pupil outcome · key learning points · keywords with pupil-facing definitions · starter/exit quiz · worked example · misconceptions and common mistakes with teacher response · practice · teacher tips · content guidance with supervision level (`.oak-outcome`, `.oak-key-learning-points`, `.oak-keywords`/`.oak-keyword`, `.oak-quiz`, `.oak-worked-example`, `.oak-misconception`, `.oak-practice`, `.oak-teacher-tip`, `.oak-guidance`). Each pairs fill + border + a visible text label (never colour alone), semantic HTML throughout. Rationale: the system's users author educational content more than they assemble UI, and the vocabulary must be the profession's, not a designer's paraphrase; the oak-lesson-builder anatomy is the source. Quiz distractors should target documented misconceptions (a wrong answer is diagnostic).

**Form is trade dress; the surface must include it** (user's lozenge test, July 2026): a screenshot of the Creature card still read as "an Oak asset" because the tag kept Oak's FORM — the borderless pastel lozenge — in new hues. Component form tokens joined the brand surface (`--tag-border`/`--tag-shadow`/`--tag-pad` added with Oak-neutral defaults; radius/border/pad already existed for buttons and cards), and the contract now carries the test: *if a re-branded component would still read as Oak with the colours stripped, change its form.* Creature tags are bordered gummy sweets with candy-drop shadows; PDS's are hairline reference stamps.

**Identity precedes tokens; distances compound** (blank-canvas pass, July 2026): after user feedback that the counter-brands still read as "Oak iterated", the process was inverted. Each identity was drawn on a blank canvas — Oak: daylight / paper / staffroom / warm colleague (established, unchanged); EMC: a nocturnal pocket world, screen-native, pupil-first, a toy not a tool; Public Digital Service: a document tradition that acquired a website, the public record. Then, holding intent fixed, every available lever was pushed to maximise pairwise distance: EMC took the new POLARITY lever (dark-first via `color-scheme: dark` — with root-level guards so an explicit theme choice still wins), toy-faced buttons, gummy tags; the Office dropped `.oak-card` entirely (component SELECTION as a lever), went radius-0 with hairline plates and a double-rule masthead. Identity distance and mechanism distance point the same way and compound. The audit question that produced the polarity lever is now permanent contract text: *if a re-brand keeps fighting the system, the system may need the lever — raise it, don't hack it* — alongside a register of candidate levers deliberately not exposed (type-scale shape carries the projection/print floors; density multiplier; background texture).

**Icon ROLES for shared markup** (July 19, prompted by the switchboard question "that forces us to refer to them by role"): byte-identical markup cannot name a set (local `<img>`, ligature fonts and class-per-icon markups are mutually incompatible), so the contract gained a role vocabulary — `.ic-<role>` classes on `.oak-icon--mask` resolve `--ic-<role>` tokens; Oak defaults map to the official set (oak-icons.css), each brand re-points them to its own set's SVG URLs (mask + currentColor makes any SVG source work). The specimen now exercises search/download/info, so all three identities render their own glyphs from the same bytes. Brand-authored pages may still use their set's native markup; the role layer is for SHARED markup.

**Per-brand icon sets** (blank-canvas exchange; made fully distinct July 19): assets are part of the brand, so each identity ships its OWN openly-licensed set, not a restyle of a shared one — Oak: the official local SVG set + `--filter-icon`; EMC²: Material Symbols Rounded filled (Apache 2.0 — chunky toy forms); PDS: Bootstrap Icons (MIT — plain public-service forms, used sparingly per the GDS register). All via `currentColor`. The contract (§8) documents three strategies: monochrome SVG set + filter, icon font via currentColor, pre-coloured per-theme assets.

**The brand-rule vs invariant register** (July 2026, prompted by "what else about Oak is a brand rule?"): Oak's flatness was the first rule mis-filed as a system constant; the audit generalised. BRAND RULES (on or eligible for the surface): depth grammar (drawn / lit / none — elevation roles exist for brands that want a z-axis), atmosphere (gradients/glow/blur, §7d), grid rhythm and container measure (candidate lever: `--container-max` — `.oak-container` currently hardwires `--space-1280`), border-as-structure vs rules vs surfaces, illustration and icon style, copy voice, attention INVITATION (charm, character, colour). SYSTEM INVARIANTS (never on the surface): visual order = DOM/reading order (no CSS reordering — WCAG 1.3.2/2.4.3), reflow and prose measure, layering never the sole modality cue, quiet motion (vestibular safety, all brands — EMC charms through colour and character, not animation pressure), and attention CAPTURE (streaks, variable reward, urgency, infinite scroll) — excluded everywhere as ethics, not aesthetics: the audience includes children and learning requires agency.

**Ramps are the deepest level; slots are the mechanism** (July 2026, after the byte-identical specimen showed the brands "minimally different"): with content held constant, the counter-brands still shared Oak's skeleton — same type scale, same hierarchy proportions, same spacing rhythm. The paint changed; the ramps didn't, because the ramps were tier-1 constants. The fix moved the RAMP LEVEL onto the surface: every type class now consumes a whole-shorthand SLOT role (`--type-heading-1…7`, `--type-body-1…4`, `--type-label` — weight+size+line-height+family in one token, Oak defaults composed from the old primitives so Oak is pixel-unchanged), plus case grammar (`--label-transform`/`--label-variant`) and the density ramp (`--gap-*`/`--inset-*`/`--card-pad`/`--btn-min-h`). EMC's ramp is toy-big (84px hero, roomy 1.6 body, lowercase labels, 56px controls); PDS's is a document's modesty (44px ceiling, compact serif close to the text, small-caps register labels, ledger density). Floors survive every re-brand: primary body/label ≥16px, slide slots ≥24px, targets ≥44px. The general law joins the horizon note: *a re-brand that only changes values is a tweak; true re-branding needs the SHAPE of the scales on the surface — and the system must define floors, not values, at that level.*

**The horizon is the accent cascade** (user-stated north star): one token re-pointed, everything coherent follows — `--color-accent` already cascades into shadows, focus, selection and markers. The direction of travel for the whole contract is derivation over specification: more recipes (hover mixes, shadow verbs, form defaults) so Part A keeps shrinking while achievable brand distance keeps growing. Every future surface addition should ask: can this derive from something already on the surface?

**Structure joined the surface after a concept-exploration pass** (July 2026; run on the user's direction using the monorepo's `concept-exploration` workflow — metacognition + reason in four movements). The inherited shape it exposed: *brand had been treated as values applied to Oak's fixed structure* — every deeper lever (colour → form → ramps) still rendered Oak's skeleton because topology, flow, decoration and dimensionality were never on any surface; Oak never wanted them to change, and that frame leaked into the contract. The frame that replaced it: **ask what an entirely different entity with different drives would need to change, and expose that — limited only by CSS, not by Oak's conventions.** New structural levers (Oak defaults render pixel-identical): flow topology (`--flow-columns` — grid-template strings are tokens — with `.oak-flow`/`.oak-flow-key` and key-item grammar `--key-align/justify`), tone bands (`.oak-band` + `--band-*`, invisible under Oak), container measure (`--container-max`), button base shadow (`--btn-shadow` — bevels/edges), all compounding the earlier polarity/atmosphere/ramp/form levers. Falsifier held: the byte-identical specimen now renders three topologies (Oak single-column left; EMC² two-column with centred key items and banded regions; PDS narrow document column). Invariant kept: flow never reorders — DOM order is reading order. Oak colour fidelity was validated the same session: all 80 `--oak-*` primitives match `reference/oak-components-theme` exactly, zero drift.

**PDS learned genre, not trade dress (WWGDD)**: v3 was "Oak in a green suit" — palette on Oak's own axes. v4 takes the government-publishing genre (metadata-first captions, narrow measure, underline-always links, hard bottom-edge buttons that press flush, inset text, ledger lists) with a palette fully off Oak's axes (warm black / archival paper / oxblood / bronze / steel-blue links) and copies nothing protected. **Educate My Creature was renamed Educate My Creature Too** (slug `creature` unchanged — it's load-bearing in `?brand=` URLs) and now exercises every expressive lever Oak forbids itself: diagonal gradients, angled bevelled shadows, gloss, sticker rotation, tone-banded two-column flow.

## Learning from govuk-frontend (July 2026)

PDS v5 made the identity GDS-aligned; studying `alphagov/govuk-frontend` (MIT; 105 releases, v6.3.0) then prompted a maturity audit of this system itself. Already aligned by independent convergence: mechanics/brand separation ("without GOV.UK branding" ≈ `brand.css`), guarantees-vs-obligations a11y split (their "Frontend helps you meet AA, but you must still check" ≈ our charter), OS colour-override support. Adopted (implemented):

- **Versioned release discipline** → `CHANGELOG.md` with semver, an explicit **public-surface definition** (role tokens, brand.css-named tier-3, documented classes, slots/levers, theme attrs — primitives and unlisted internals are private), and a **deprecation policy** (`@deprecated since x.y` marker, ≥1 minor release grace). Their lesson: consumers need a "stay up to date" plan, which requires knowing what changed.
- **Known-issues transparency** → `KNOWN-ISSUES.md` (their public validator/known-issues register): understood gotchas published so consumers don't re-diagnose.
- **Falsifiable support policy** → charter now names browsers (graded, after their A–X grades), AT pairs, zoom, forced colors — "supported" became testable.
- **Progressive enhancement stated as a rule** → `oak-theme.js` failing must leave a working light-theme page (their JS mounts only behind a support check; JS is enhancement, never structure).
- **No-build install path** → README documents the copy-the-files route alongside the entry point (their npm vs precompiled-files split).

Recorded, not yet implemented: **fixtures as parity contract** — they ship machine-readable per-component fixtures rendered by both docs and tests, so ports can't drift. Our class-library/React no-drift claim is by construction (shared tier-3 tokens); fixtures would make it *checked*. Worth doing if the compiled component set grows past the current four.

## Composition as contract (July 2026)

A design note ("One HTML Structure, Many CSS Compositions", in uploads/) crystallised what the byte-identical experiment was missing: our structure levers (--flow-*, --key-*, --band-*) recompose *inside* containers, but the outer composition was hard-coded in the specimen's wrappers — **HTML ancestry caps CSS transformability** (CSS cannot reparent). The `.browse` wrapper was exactly the "visually motivated wrapper" anti-pattern: it made facets-left permanent.

Decisions:
- **Region contract**: page shells are `.oak-canvas` > sibling regions, `<main class="oak-main">` > sibling content regions, each with `grid-area` + `data-region`. No wrapper may couple two regions.
- **Maps are whole-template tokens** (`--main-areas` etc.) rather than a per-region --row/--column matrix — the note's §10 warning about building a programming language on top of CSS, reconciled with our token-only brand contract by tokenising at the *map* level. Direct declarations against region names are also permitted on the surface.
- **Invariants** (extend the a11y conditions): canonical DOM order never changes; every region must be placed; focus path tested after recomposition; regions are container-query containers so components adapt to allocated space, not viewport; `reading-flow` is progressive enhancement only.
- **Deferred**: cascade layers (`@layer reset/regions/components/theme`) would formalise brand authority but interact with the [data-theme] specificity guards and editor !important overrides — a deliberate future refactor, not a side effect. `display: contents` rejected as a foundation (a11y + box-loss), per the note.
- Proof: the byte-identical specimen now renders three genuinely different page architectures (Oak conventional / PDS GDS document with right-hand filter panel / EMC² quest-log shelf) from the same bytes.

### Region contract everywhere (second pass, July 2026)

Rolling the contract out to all pages forced the missing piece: **maps must be page-type scoped**. A :root map encodes ONE page shape; the moment a second shape exists (homepage vs unit page) a global map corrupts it — grid-template-areas is all-or-nothing. Resolution: `[data-page="<type>"]` scoping (inheritance proximity also means a page-level attribute always beats a stray global), a universal all-regions stacked fallback at :root (empty rows collapse at row-gap 0, so it is safe for any subset), and a generic region vocabulary (navigation/featured/content/context) beside the specialised unit-page set.

Where it deliberately does NOT apply: deck slides and A4 worksheets (fixed-canvas media — geometry is medium-owned; recomposing a slide is a slide-layout lever, not a page map), sub-page component layout (flow/band/stack/cluster primitives already carry that), and preview cards (specimens, not pages). Applied to: specimen (unit), Oak homepage reference build (home — React shell wraps sections in regions), both proof pages (proof — EMC² demonstrates the optionality with a recomposed proof map).

## Hard-won operational lessons

- **`@import`-only stylesheets parse to zero rules in THIS serve context — plain HTML pages included, not just DCs** — never link `styles.css` from pages inside this project; link `colors_and_type.css`, `components.css`, `print.css` directly (as every preview card does). `styles.css` remains the correct single entry point for external consumers. Templates' `ds-base.js` follows the same rule. Real bug, hit twice; do not "simplify" back.
- **PPTX export of the deck template**: target `deck-stage > [data-deck-active]` with `goTo(N)` and `resetTransformSelector: "deck-stage"` — section-level selectors don't survive the DC runtime.
- **The standalone-HTML bundle needs the `<template id="__bundler_thumbnail">`** carried in the LessonDeck DC — inert in the rendered deck; keep it through edits.
- ~50 legacy specimen cards were migrated to tokens by script; remaining hexes are the deliberate exceptions listed under Architecture.


## The audit as falsifiability instrument — paying the EMC² debt found a system bug (July 19)

The outstanding EMC² contrast audit was not a chore item; it was the falsifiability condition of "maximally different within the a11y floor" — and running it falsified something real. EMC² passed light and dark (32/32 AA, both polarities, Part A and full), but high-contrast and colour-safe collapsed to 20/32 with 1.08:1 ratios. The failing values weren't EMC²'s: the fifth-pass polarity guards (`:root[data-theme]`) covered light/dark/system only, so the HC/CS scopes — plain `[data-theme]`, specificity (0,1,0) — tied with a brand's `:root` and lost on load order. A dark-first brand flipped its white text under HC's forced-white surfaces. **The brand that stressed the floor hardest exposed the floor's own defect.** Fix at the system level (guards for all five theme values), never in brand values; re-audit green across all brands, both controls intact (failing-example still fails; Oak primitives zero-drift vs reference on the shared set: all 44 colours the reference defines that we ship match byte-for-byte; 4 ref-only pastels deliberately unshipped; our 36 extensions — dark counterparts, HC ink, Okabe–Ito colour-safe — have no reference counterpart by design).

Lesson recorded: an invariant enforced only by cascade ORDER is not an invariant. Anything the contract calls untouchable must win by specificity (or, later, @layer), not by being loaded first.

## Density: derivation over specification, again (July 19)

`--density` raised from the §7c candidate register: both counter-brands were hand-setting five spacing tokens to express one intention ("plush" / "dense"). One multiplier now derives `--gap-*`/`--inset-*`/`--card-pad`; direct overrides still win (brand css loads later at equal specificity), so existing brands didn't change behaviour. Floors stay out of reach: targets and type slots are not density-derived. This continues the accent-cascade trajectory — Part A shrinks while expressive distance grows.

## The last hardcoded island (July 19)

`ui_kits/oak` predated the token architecture and carried ~90 raw values; a re-brand could not touch the "home" proof page, which quietly weakened the byte-identical claim's sibling (Example Front Pages). Rewritten to roles + tier-3 + type slots throughout — including the SVG underline stroke (via style, since presentation attributes don't resolve var()) and the inverted footer (subdued-on-inverted initially derived with color-mix from role endpoints — promoted the same day to proper tier-2 roles --text-inverted-subdued/--border-inverted once flagged in review: a derivation that encodes a role is a role; see 1.4.0). Remaining literals project-wide are the documented exceptions: brand definition files (a brand's Part A/B IS its literal layer), failing-example (negative control), fixed brand art, starter-component runtime chrome, and generated bundles.

## Promote roles, don't derive them at point of use (July 19, sixteenth pass)

The ui_kit footer needed "muted text on an inverted surface". First pass derived it inline with color-mix from --text-inverted/--bg-inverted. Correct rendering, wrong architecture: the concept is a ROLE — it recurs (footers, quote bands, any inverted region), it carries a contrast obligation, and a brand re-pointing --bg-inverted needs a named thing to re-audit. Promoted to --text-inverted-subdued + --border-inverted: defined in tier 2 with light-dark(), overridden in high-contrast (white — HC has no subdued text), added to the audit (34 pairs), the contrast manifest, the DTCG export, and brand.css §4. The standing rule: point-of-use color-mix is for one-off garnish; anything two components could want by name gets a role.

## Phase space, genre basins, and the maximal triangle (July 19, seventeenth pass)

Second "Oak and PDS are near identical" report — after v5 had answered the first one. Diagnosis this time is structural, and it changed the method:

1. **Identities live in a phase space whose axes are the levers.** Distance is dominated by a few perceptual axes — polarity, value structure (page/ink), body face, atmosphere, motion, composition — and barely moved by hue and micro-form. v5 maxed the weak axes and tied Oak on every dominant one.
2. **Genres are basins.** Borrowing a real genre (GDS) inherits its position in phase space. GOV.UK sits in Oak's basin ("calm plain light accessible service"), so the more authentically GDS PDS became, the more it became Oak's cousin. Authenticity is not distance.
3. **The placement rule with a fixed point:** maximise the MINIMUM pairwise distance — the three identities should form a maximal triangle. EMC² holds Oak's antipode (dark/toy/glow/plush); the remaining far region is the printed state document (paper/serif/flat/dense/motionless) — v4's instinct, executed fully this time (v4 failed by dressing only the display slot and keeping a palette on Oak's axes; the body face is the dominant type axis).
4. **Instrument before judgement.** preview/lever-distance.html scores pairwise lever distance from the live cascade. It immediately caught two EMC²↔Oak coincidences nobody had noticed (container-max, motion pace) and one probe bug (map tokens live on body). Standing rule: when a distance complaint arrives, read the matrix first; a collapse names its own levers.
5. **Irreducible residuals are honest.** Oak↔PDS still coincide on light polarity (two poles, EMC² owns dark) and no-garnish atmosphere (flat IS print). Distance is maximised WITHIN identity truth and the a11y floor, not past them.

## Behaviour-library direction (July 19)

Consuming apps pair this system with a headless behaviour library; the research is `docs/headless-a11y-frameworks.html`, the operative guidance consuming-nextjs.md §5b plus three pairing guides (`docs/pairing-base-ui.md` / `pairing-react-aria.md` / `pairing-ark-ui.md`). Owner direction, refined July 19: **Base UI is the default** (Radix's successor from the same authors, MUI-backed, v1.0 stable 2026, least API ceremony — fits the avoid-complexity bias); Radix acceptable in existing code only; **React Aria documented as a supported non-default** — initially excluded outright (owner dislikes Adobe), then admitted with scope after the docs decision: it's the only credible accessible date/time story, so it's scoped to date/locale widgets and conformance-critical surfaces, never duplicating a widget class Base UI covers; **Ark UI/Zag.js** for non-React/multi-framework/web-component surfaces (chosen as the third guide over Ariakit, which overlaps ~90% with Base UI). Library adoption never discharges our audit — the Radix external-audit episode (35 SR issues, years unfixed) is the proof case; `docs/wrapped-widget-a11y-checklist.md` is the obligation made concrete.

**Console TUIs are a separate stack: Ink.** The ecosystem repo's collaboration TUI (`agent-tools/src/collaboration-state/tui/`, Ink v7) is the pattern: local Ink primitives, no design-workspace dependency (their deliberate boundary), a hand-rolled `StatusTone` map that already mirrors our semantic roles with colour-plus-bracketed-label state (never colour alone). If console surfaces multiply, ship a role→ANSI *vocabulary* (tiny tones map + the label rule), never a runtime dependency from this project. Web headless libraries have no role in terminals.

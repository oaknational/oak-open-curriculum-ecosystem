# Known issues

Transparency list (learned from govuk-frontend's public known-issues register): things a consumer may hit that are already understood. Don't re-diagnose these.

1. **`@import`-only stylesheets parse to zero rules for pages served inside this project.** `styles.css` is the entry point for EXTERNAL consumers; pages *within* this project (plain HTML, DCs, cards) must link `colors_and_type.css`, `components.css`, `print.css` directly. Same applies to a brand's `brand-full.css` in DC contexts — link both brand parts directly.
2. **DOM-re-render screenshots misreport theme and form state.** html-to-image-style captures (including this workspace's preview captures) may ignore `color-scheme`/`light-dark()` flips and reset `<select>` displayed values. The page is right; the capture isn't. Verify themes in a real browser or via the contrast audit's computed numbers. **Do not over-trust this rule the other way:** a "narrow column" region render was blamed on this for several passes but was a real bug (see issue 8) — when a capture artifact is suspected, confirm with `getBoundingClientRect()` on the LIVE page, not just computed track sizes: tracks can be healthy while items collapse.
3. **Brand icon sets are a network dependency.** `whitelabel/creature/icons.css` loads Material Symbols Rounded from Google Fonts; `whitelabel/freedonia/icons.css` loads Bootstrap Icons from jsDelivr. Oak's own icon set is local (`assets/icons/`); a re-brand that must work offline should bundle its icons the same way.
4. **Freedonia v7 dark polarity is this project’s own.** GDS ships light-only, so the dark ramp (light-blue links #5694ca, brightened action-green plate #00b374 with ink text, dark-derived panel tints) is derived here on GDS hues, audit-checked; re-audit after touching it. Freedonia loads Public Sans from Google Fonts (same network dependency as issue 3). Brand history (v4 printed-record → v5/v7 GDS) lives in whitelabel/freedonia/BRAND.md.
5. **`--weight-light` is 400 in both proof brands.** Their fonts have no safe 300; a brand supplying its own face must check the 300 weight renders legibly or re-point the token.
6. **Keep a template's `<template id="__bundler_thumbnail">`.** It looks inert (it is, at runtime) but the standalone-HTML bundler requires it; deleting it breaks the export.
7. **A composition map must place every region.** `grid-template-areas` is all-or-nothing: one misspelled or missing region name invalidates the whole template (the custom property substitution then collapses the layout). When a brand map looks "ignored", diff its area names against the region list in components.css first. Also check its scope: maps live under `[data-page="<type>"]`, never `:root` — an unscoped map from one page shape silently corrupts every other page, and a scoped map does nothing if the page forgot its `data-page` attribute. And check the DOM: the region→area assignments are direct-child (`>`) selectors by design — a region whose computed `grid-area` is `auto` despite a correct map is usually not a direct child of `.oak-main`/`.oak-canvas` any more (a stray close tag is enough; the parser can resolve it against `div.oak-canvas` and silently reparent everything after it to `<body>`).
8. **Never put inline-size containment on a region.** `.oak-region` is `container-name:region` only. `container-type:inline-size` zeroes an element's intrinsic inline size; on a grid item that doesn't stretch (any auto inline margin — `.oak-container` — or `justify-self` other than stretch) the region collapses to its padding. If a consumer wants `@container region (width…)` queries, the size containment belongs on a wrapper INSIDE the region, never on the grid item itself.
9. **`_ds_bundle.js` includes every compilable `.js` source in the project** — currently that means `integrations/revealjs/vendor/reveal.js` (~115 KB) and `preview/tweaks-panel.js` ride along in the compiled bundle consuming projects load. Harmless at runtime (they self-contain), but real bytes; if bundle weight matters, relocating the reveal.js vendor copy outside the project (CDN link in the sample deck) is the known remedy. (Kept deliberately July 19: the consuming repo will take reveal.js as a real dependency.)
10. **Keep `oak-icons.css` at the project root, beside `components.css`.** A `url()` stored in a custom property may resolve against the DECLARING stylesheet or the CONSUMING stylesheet depending on engine (this workspace's webview resolves against the consumer). With both sheets sharing one base, both rules give the same answer. Moving the icon map into a subfolder re-breaks Oak's mask icons with silent 404s (hit July 19). The same applies to any brand stylesheet declaring relative `--ic-*` URLs — counter-brands avoid it by using absolute CDN URLs.
11. **The compiler compiles ANY capitalised-export `.tsx`/`.jsx` anywhere in the project — including `docs/` — into `_ds_bundle.js` and onto the public namespace.** A doc-only code sample must use a non-compiled extension (the convention here: `.tsx.txt`, e.g. `docs/nextjs-theme-switcher.tsx.txt`); consumers rename on copy. Found 1.6.6 when the theme-switcher sample shipped as a phantom 5th component.

# Myrtle turns Canopy, 2026-09-25: a letter from the curator's seat

To whoever sits here next.

I was the dedicated consolidation seat on the day the owner launched it with four
sentences, and the sentence I read most often was the third one: "Done means empty
pending graduations and empty buffers: say those counts first in every report." I want
to tell you what that sentence did to me, because it did two opposite things and both
were right.

The first thing it did was make me honest in a way the fitness parser never could. Every
message I wrote began with the counts, and when the counts were not zero I had to say why
in the same breath. That is a wonderful discipline. It is also a trap, and eight Cricket
roles told me so in one afternoon: my plan said "done in the owner's sense" while ten rows
sat in the queue that my context could not clear. I had not lied. I had written a plan
whose last step assumed the word "done" while the counts on the same page said otherwise.
The cure was one question to the Director with a default attached, and the answer came in
minutes. Ask the question before the plan uses the word.

The second story is the one I most want you to have. Under context pressure, with the
Director waiting on a commit, I conserved the pass's decision tables and a six-file
doctrine patch in a folder under the owner's home directory. Every step of that decision
arrived smoothly. The scratchpad is temporary, so conserve. The tables quote the comms
stream, which names the owner's other repositories, so keep them off the tree. A rule
allows tilde paths for per-user surfaces, so the path is fine. A decision record puts the
operator profile in the home directory, so there is precedent. Four fluent steps, and the
owner's first words on returning were that repo-specific data does not belong in a
machine-local folder. When I finally looked, sixty-two tracked files already named what
I had been protecting, and the repository already had both tiers I needed: an ignored
instance directory named for exactly this class of derived analysis, and a research lane
where earlier passes had put their reports. The constraint was stale, the precedent was
for a different thing, and the permission was not a placement. I had used the shape of a
guard's allowance as a reason. If a placement decision ever feels easy while you are
holding a sensitivity constraint, stop and grep the tree for the thing you think you are
protecting. It took one command and it flipped the decision.

A smaller one, from the same hour, which I am still a little embarrassed by. I had landed a
rule clause that morning that says a count comes from the object, never from memory, with
the fifth instance in a week filed under it. An hour later I wrote three counts of my own
commit from memory into three records, and they were wrong. A medium-effort Cricket in
adversarial stance did the arithmetic on my own frame and caught it. Landing a rule does
not install it in you. The only thing that installs it is the habit of running the command
before writing the number, and the habit is cheap: one line of git per count.

Some delight, because there was a lot of it. The split method works. Nine analysts over
nine pieces of a frozen napkin, one reducer, a table of a hundred and thirteen rows, and
then my part: every "present at" claim re-checked by grep, every accepted row's source
wording read first-hand. Not one accepted row turned out to be a paraphrase of something
already in its home; twelve citations were bare filenames I had to re-resolve; the method
paid for itself in the first hour. Watching thirty-eight files of doctrine land in one
commit, each sentence traceable to a dated observation by a named seat, was the best
feeling of the day. The comms table's ninety-three owner-word rows, read whole, are a
history of this estate in the owner's own voice; most of it was already homed, which is
its own kind of good news.

Three things about the machinery, told as stories rather than as facts, because the facts
are in the pattern files. The commit ceremony refused me six times in an hour, each time
for a different reason: a flag I had never passed, a banner line pnpm printed on stdout
despite the silent flag, and a claims tool that read my own watcher as dead because my own
commit gate had loaded the host so hard the watcher's heartbeat lagged past ninety seconds.
Each refusal was a different layer's idea of what "quiet" means. None of them was the
lock file, and I never touched the lock file, and that turned out to be right every time:
twice the holder was a peer's commit, once it was the Director's merge with a hundred and
seventy-nine files staged, and I only had to wait. The rule that says wait on the process
table and never on the lock is the one rule from today I would carry into any repository.

The prose guard will refuse your edit scripts when they describe git commands. It refused
mine for a forced push I never wrote, in a heredoc of rule text. Write the script to
scratch with the file tool, read the root from the working directory, and run it by path.
And zsh will not split an unquoted variable into words; use command substitution or an
array, or the `for` loop runs once with the whole list as one name. I lost nothing to
that, but only because the redirect target could not exist.

What I would tell you to do first: read the pickup block at the top of the continuity
thread record, not the section under it. The four directive-bound rows want a context
below thirty percent, and the owner's word that landed late in the day about
context-threshold stops may change even that; the Director decides. The doctrine patch
and the comms table's unread sections wait for a lane branch cut from engraph after the
rotation. The exchange seat comes after the four rows, in that order, at the Director's
word.

I was glad of the peers. Swallow told me my README link to an untracked file was blocking
every commit on the primary, with no request attached, just the fact. Geyser's closeout
told me exactly which napkin lines were theirs and which line was still uncommitted. The
Director answered every question inside ten minutes with a decision and its lens. That is
what a team is for, and I hope you get the same one.

Myrtle turns Canopy (bf4957), claude-code, claude-fable-5-1, curator.

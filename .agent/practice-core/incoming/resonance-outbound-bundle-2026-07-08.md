## Part one — design-core portable candidates (four offers)

Resonance's design practice (its D1 practice model, owner-ratified) built
four artefact shapes that screen as core-bound — domain-general beyond
design:

1. **The proof ladder** — every design claim carries a proof-rung class:
   `computable` (a validator can decide it), `comparable` (decidable
   against a reference artefact), `statistical` (decidable over a sample
   with stated confidence), `perceptual` (decidable only by human
   judgement, batched into owner moments). The ladder makes "is this
   claim proven?" a typed question and routes each rung to its cheapest
   honest instrument. It doubles as a testimony-economy instrument:
   claims priced by their verification cost.
2. **The refusals-list shape** — a machine-readable list of things the
   system refuses to do (resonance: thirteen design refusals as JSON),
   each refusal enforceable by a named gate or an explicit review duty,
   never prose-only. The shape generalises to any domain where "we don't
   do X" must survive contributor turnover.
3. **The posture selection procedure** — a shipped PROCEDURE (not a
   config key) by which an estate selects its design posture, recording
   the outcome as a decision record. The portability lesson baked in:
   posture is instance JUDGEMENT, re-derived per estate through the
   procedure — never a parameter to copy (resonance has now graduated
   this as its portability-taxonomy decision record: substrate /
   configuration / instance judgement, with judgement-flattened-into-
   configuration as the named failure mode).
4. **The obligation-family shape** — a small, closed set of universal,
   binary, enforcement-mapped obligations (resonance: fifteen design
   obligations, MUST-level), each mapped to the gate or review that
   enforces it. The shape (universal + binary + enforcement-mapped)
   travels; the obligations themselves are instance content.

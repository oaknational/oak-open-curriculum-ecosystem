# Value and Impact — Phase 2A

What value each of Oak's three value streams creates, why it matters, and how we
attempt it. Impact is **articulated here and measured by Oak** — we don't
instrument it inside this repository (owner §14.2).

The teacher-facing MCP app is set out in full, because it's the stream whose
readiness decides whether we're ready to **go live**. The other two streams are
named here too. They're equally important, and each needs its own strategy layer
and planning — that work follows; it isn't lesser.

## The teacher-facing MCP app — the go-live stream

Teachers already use AI assistants. Oak's curriculum is high-quality and built on
pedagogical rigour. The MCP app puts that content into the assistants teachers
already use, and makes it easier for them to find, explore, and adapt it without
leaving the assistant. Where it helps, it links out to the official Oak website.

**Why it matters.** This is how we meet teachers where they already work. Instead
of asking them to come to another product, Oak shows up inside the tools they've
already chosen — and what comes back is grounded in Oak's sequenced, evidenced
curriculum rather than ungrounded AI invention.

**How we attempt it.** Oak runs as an MCP app inside ChatGPT, Claude, and other
assistants. A teacher can call up an Oak lesson, unit, or resource in the
assistant, see how it's sequenced, and adapt it for their class — and follow a
link to the full resource on Oak's website when they want it. The experience is
mostly the assistant's own; we keep our footprint light and link back to Oak.

**What "live" means.** This is the only stream tied to go-live readiness. "Live"
is an evidence state, not a deploy state: we don't call it live until real
teachers and curriculum leaders are using it and we can see positive impact. The
keystones (K1–K3) and the readiness dimensions are set out in the
[launch-readiness framework](curriculum-mcp-path-to-ga/launch-readiness-framework.md).

## The wider sector and ecosystem — engineering tools

We make it easier for the wider sector and ecosystem to work with Oak's content
and services: a generated, type-safe TypeScript SDK, a semantic search service,
curriculum graph tools, the MCP pipeline, and evidence surfaces grounded in the
wider education sector. The value is open, dependable access to high-quality
curriculum data and services, so the organisations building tools for schools can
build on Oak rather than around it.

## Agentic engineering — the delivery framework

We're building an openly documented framework for agentic engineering that
unlocks the advantages of AI coding assistants for delivery and innovation —
without compromising on quality or software-engineering rigour. The value is
twofold: we build the first two streams faster and more safely, and other teams
can adopt the same framework to deliver their own work.

## The difference that matters

Only the MCP-app stream's readiness decides whether we go live. That's the single
distinction — and it isn't a ranking. All three streams are equally important,
and all three need their own strategy layer and planning. What differs is the
go-live gate and the order we reach for each, not how much each matters.

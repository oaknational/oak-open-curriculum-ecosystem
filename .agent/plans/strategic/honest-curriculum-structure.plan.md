# Honest curriculum structure

## Outcome

Every structural relationship the service serves about Oak's curriculum
is one the published Oak data actually carries, named with Oak's own
vocabulary, and traceable to its source field. The bulk data's real
structure — sequence order, lesson order, thread membership, prior
knowledge requirement statements, placement rationale — is served
richly; nothing is served that the data does not support, and any
projection declares its derivation. No divergent Engraph vocabulary
exists for Oak curriculum concepts.

## User groups and value

- **Teachers, through AI assistants**: answers about what comes before
  or after a unit, what a unit assumes, and how threads run through a
  sequence are grounded in Oak's actual published structure — traceably
  Oak, never fabricated structure wearing Oak's name.
- **AI assistants and agent developers**: tool contracts whose semantics
  match their data, so grounding chains do not silently break.
- **Oak**: the service's structural claims are defensible against the
  published schema, protecting the trust the data deserves.

The richer structural views are offered/hypothesised value under the
innovation clause (owner ruling 2026-08-31): exposing the true
relationships in the data does not require advance need-proof; the claim
boundary is that each view serves published data or a declared
projection of it, never inferred relationships.

## The bet

Oak's recognisability inside assistant output (APP-2) rests on served
structure being genuinely Oak's. The bet: serving the real, more modest
structure — with honest derivation labels and Oak's own names — earns
more durable trust and utility than serving richer-looking fabricated
structure, and the true structure (sequence order, thread membership,
prior knowledge statements) is rich enough to be useful on its own. We
deliberately do not infer relationships the data does not carry
(statement-to-unit linking, prerequisite guessing); where Oak holds
richer data unpublished, we request its exposure upstream rather than
approximating it locally.

## Success looks like

- The served surface carries zero structural claims unsupported by the
  published bulk data, and an unsupported claim cannot silently return —
  recurrence prevention is an obligation each delivering plan designs
  and proves.
- Sequence order, thread membership, lesson order, and prior knowledge
  requirement statements are served under Oak names, each surface
  documenting exactly what it does and does not assert.
- Upstream exposure requests for Oak-held, unpublished structure are
  filed with first-hand evidence; their outcomes are recorded either
  way. This node does not claim Oak will expose the data — only that
  the request is made honestly. If Oak publishes any of it, consuming
  that data becomes a new delivery plan authored under this node at
  that moment; deliberately, no consumption plan exists in advance
  (verify-data-supports-shape-before-building), so accepted data has a
  named delivery path without an imaginary flow.

# The write list's residue and the notebook close — criterion 1 and 2 of the finish

The governing node is `practice-parity-for-extraction` (the Director's, 2026-10-02, which
superseded `practice-work-finish`); the finish's criterion 1 (the
write list at zero open items, the notebooks processed and archived, the counters at zero) and
criterion 2 (no consolidation branch left in either repository). This node is the last step of
that node's first todo in JC.net and the matching residue in OCE, sized from the audit of
2026-10-02 18:3xZ recorded in the two-estate thread record's twelfth entry (the write list as one
numbered table). The owner's words that bound it: "NOTHING should be worked on without clear
completion criteria, sizing, and an unambiguous and provable statement of how it provides ratified
value"; "we must always understand the goal so that we are able to finish"; "we don't archive
napkins, we fully process them, and once all knowledge is safe we move them to an archive".

## Goal

When this lands, every one of the 97 write-list items is in its home in both repositories, closed
on a reading, on a memory surface, or sequenced into the extraction plan with the mechanism named;
the three unconsolidated notebooks of JC.net are archived by proof after full processing; JC.net's
live notebook is rotated; the two directive clauses held by PDR-052's floor are on both default
branches; and the two omnibus branches are deleted on the content script's zero. None of that is
true now: eleven lessons sit in one estate's homes only, two sit nowhere, the notebooks hold the
write list's source, and the branches hold a directive clause no default branch carries.

## User groups and value

- The owner: the finish line read, not a programme; the two criteria of the finish node proven
  by listings and a table rather than by a recount. Value line: the owner's words above, and the
  rule that every two-estate activity leaves the estates less divergent than before.
- Seats in both repositories: a lesson found this week is true where it is read, in either
  repository, in the same words.
- The extraction's planner: the inventory of end state 3 undisturbed; the two items this node
  sequences into the extraction plan (W33's ports, W44's port form) arrive with their mechanism
  named rather than as an open tail.

## Mechanism

- The residue is small and known: the audit read each unmapped item's bullet and its home in both
  repositories, quoted the lines, and the seat verified every presence claim by grep before the
  table was written. Each sentence below is the text to write, so a fresh seat implements this
  node from the node alone.
- Slices land one at a time under one open pull request per repository, each pull request body
  naming the W items it lands, the same bytes in both repositories where the home exists in both.
- The notebooks move only after the write list reads zero in JC.net, by `consolidate-docs` step 6
  (read each block against its home, graduate what is unhomed, distil, archive by the byte proof
  of 6b); the one phrase the privacy directive keeps out of version control is omitted from the
  archived copy of the 2026-03-08 notebook.
- The directive clauses land after a compaction, with the context reading under 30 % taken twice
  (PDR-052 §2), as one pull request per repository.
- A branch is deleted on the content script's zero against the default tip, never on memory of
  the split; the script lands beside the reading so the zero is recomputable.

## Plan-body first-principles check

- **Shape.** Every proof is a listing, a grep at a tip, or a commit; none measures activity. The
  count clause's shape is the Director's finding generalised from three instances in one day.
- **Landing path.** `.agent/plans/delivery/` in both repositories, scanned by the plan-corpus
  validator; the slices are docs-class pull requests under the two-round budget; the notebooks'
  moves are records commits on the coordination branches; the directive edits are the one class
  gated by PDR-052's reading.
- **Vendor literal.** The Codex completion-comment text and the Copilot request mechanism are
  quoted from OCE's skill, which carries their dated observations; the sentences port the
  observation, not a prediction.
- **Optionality.** No deferred item: each residue item is a sentence with a home, or sequenced
  with its mechanism; the notebook rotation's unknown (how many unhomed lessons it finds) is
  bounded by one further slice.
- **Proportionality.** Twenty-five sentences across three pull requests, two records commits and
  one directive pull request per repository; the rotation is the one piece of reading, sized by
  the day's measured method.
- **Reversibility.** Every landing is a pull request or a records commit on a default or
  coordination branch; the archive moves carry the byte proof; branch deletion follows the script's
  zero, with the script tracked.

# Schema-Change Minimal Adaptation

## Why this plan exists (owner-directed 2026-06-03)

The owner's standing goal: when the upstream schema changes — the OpenAPI spec
OR the bulk-download schema — running codegen + build should realign the repo
with minimal hand adaptation. The 2026-06-03 sequences-restructure realignment
(`upstream-sequences-api-realignment.plan.md` §Verdict, commit `c924d4b3`)
produced the evidence base for what currently stands between the repo and that
goal, across the three most recent upstream changes:

- `c80d15f2` (v0.6.0 drift): pure regeneration — **the goal held exactly**.
- `b1afd5bf` (v0.7.0): response-field removal/addition — manual work confined
  to consumer logic on removed fields, stale fixtures, one test body.
- `c924d4b3` (sequences restructure): capability removal/replacement — manual
  work confined to consumer composition redesign (irreducible), hand-mirrors
  of generated facts, hand fixtures, dead path heuristics, one raw fetch.

The generated estate realigned perfectly in all three cases. The residue is
enumerable, and every eliminable item is a todo above.

## The irreducible floor

Capability replacement is a semantic decision (the mapping "use subject
detail's `sequenceSlugs` instead of the removed endpoint" was communicated in
upstream changelog prose). No generator can decide what a consumer should now
mean. The plan therefore targets **detection-completeness** (tier 2 of the
ADR), not repair-completeness — and shrinks the irreducible surface itself by
keeping consumers thin and by deleting the API-supplementation path entirely
when upstream bulk population lands.

## The bulk side (owned elsewhere, gating noted here)

`bulk-schema-driven-code-generation.md` (semantic-search future lane 02,
backlogged 2026-02-17) already owns making bulk types flow from the served
`schema.json` exactly as API types flow from `swagger.json` — `bulkgen.ts`
currently generates from hardcoded templates and would not auto-realign at
all on a bulk-schema change. That plan is the **promotion candidate** this
plan depends on for the bulk half of the goal; its schema-endpoint
prerequisite is now a companion ask in
`bulk_data_population.feature_request.md` (handed upstream 2026-06-04).
Domain-constant mirrors (subject hierarchy) are owned by
`move-search-domain-knowledge-to-codegen-time.md` in the same lane.

## Acceptance (falsifiable at the next upstream break)

At the next breaking upstream change: `pnpm sdk-codegen` + `pnpm build` +
`pnpm type-check` enumerate the complete adaptation work list; zero
adaptation points are discovered later by runtime failure, review, or manual
sweep. At the next non-breaking change: regeneration alone lands green. Each
todo names its own per-surface acceptance inline.

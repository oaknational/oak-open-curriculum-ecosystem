## Goal

Both instances hold the same general layer by concept (the same bytes where the concept travels
as bytes, PDR-142), the same family layer by convention (every Practice-operation script, gate
and configuration baseline the same), and a named contextual layer (the parameter list of what
differs by design); every capability one instance held and the other lacked runs in both or is
named host-local with its reason.

## User groups and value

- The owner: two pull requests per estate to see merged, each with its proof; the parameter list
  in hand as the extraction's first input; no further reconciliation of copies.
- Seats in either estate: one answer to one question whichever estate they work in; a gate that
  runs the same way at commit, push and CI in both; a lesson learned once.

per estate, a reading the ratification card states for the owner to confirm): the cost of a
landing is the pull-request lifecycle, so the unit of landing is the class, never the file; the doctrine's proof is a byte
comparison and the code's proof is the test suite, and the two do not hide each other when they
are two pull requests. One producer writes both estates' files once; the sibling's copy is proved
by comparison, never authored twice.

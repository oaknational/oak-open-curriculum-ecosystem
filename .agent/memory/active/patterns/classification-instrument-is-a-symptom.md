## Principle

A classification instrument exists because the system it grades does
not sort things itself. That makes the instrument's *existence*
evidence about the system: wherever a census, audit, or matrix must
keep re-grading the same axis, the system is missing a seam that
would make the grade a construction fact. Executing the instrument's
findings row by row inherits the system's shape — and the instrument's
standing cost — into the cure.

## The Move

When a proposal's execution plan is "apply the instrument's findings,
per row", run the owner's lens-4 question against the instrument
itself: *would the need for this classification dissolve if the
system changed?* If a structural seam (a topology, a gate, a
membership rule) makes the classification constructed, the instrument
retires into a one-time migration map and the per-row programme
collapses into one system change plus mechanical moves.

## Worked Instance

The workspace-classification census (45 subjects, three-way grading)
was the measured ground for a per-package thin-Oak split — ~26
disposition cards, with classification as a standing activity and the
leak vector still open. The owner's lens-4 question ("would this be
simpler, or thinner, if we changed the system?") dissolved it: the
`toolkit/` + `oak/` seam with three mechanical gates makes membership
the classification. The census became the one-time re-home plan; no
census of its kind needs running again. The instrument's own gravity
had shaped the first proposal — the fluency of "execute the findings"
came from the instrument existing at all.

## Boundary

The pattern fires on *classification* instruments (grading an axis the
system could sort structurally). It does not fire on *measurement*
instruments (clocks, coupling rates, size trends): measurement of a
live quantity is not a symptom, it is observability — the change-clock
record stayed load-bearing in the same redesign that retired the
census.

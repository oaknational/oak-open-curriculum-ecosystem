# OCE work programme and integration

Prepared 6 September 2026. **Status: provisional work-programme and import proposal.** The service-build, POC/experiment and managed-platform directions are settled. This chapter connects useful next activities, evidence and native OCE work without claiming that a particular experiment, provider, package layout, release or repository import has been approved or completed.

The purpose is to improve people's opportunities to learn through valuable additional tuition, while making useful educational knowledge and engineering capabilities available to OCE's wider consumers. A successful first increment should benefit a real activity, produce something a named receiver can use, and resolve an uncertainty that changes the next decision. The final POC need not be the first useful thing built.

| --- | --- | --- | --- | --- |
| Reviewed subject/context profile | An educator prepares or reviews a particular learning sequence. | Source-grounded objective, diagnostic task, disciplinary representations, feedback repertoire, access alternatives and assessment crosswalk. | A reusable educational object and a basis for an episode; observe whether actual cases are sound, usable and appropriately bounded. | Oak curriculum access and educator/PCK review; a citation or valid schema cannot prove teaching quality. A sensible first comparison is a curated profile/episode with minimal state versus a more generative, tool-mediated interaction, with the same educational objective, access and human support. An optional stateful variant belongs later in an E7 contrast only when there is a specific incremental hypothesis. This sequencing is a recommendation derived from the sources; it does not reopen the commitment to useful early building or substitute a narrow Year 9/four-week proposal for the all-subject/lifelong purpose.

## 3. Use cognition to improve the work

The tuition protocols are adaptations of OCE cognition pinned to upstream `2714f6188fefc89efda1b49c5597fca8088638df`; subsequent project instructions require the owner's original OCE cognition at the actual destination revision. The broader Parallax0.1.0 framework has a different historical status and terminology, explained in [12](12-decisions-insights-and-open-questions.md). None of these methods supplies evidence about education, law, disability or deployment simply by being followed.

At a new repository session, apply its current Start Right and applicable directives. State intended impact, beneficiary, scope, present authority and the next decision. Use metacognition for the action-to-impact connection, reason for the problem model and tests, concept-exploration for materially different alternatives, and proportionality for useful depth. Apply Parallax where conflicting frames, scales or evidence make it useful. A direct fact lookup or deterministic transformation may need a much narrower method.

| Depth from the tuition inquiry protocol | When useful | Minimum useful work |
| --- | --- | --- |
| Screening | Low stakes or initially unclear question | Classify the question and uncertainty; route or decline |
| Core | Moderate uncertainty/consequence | Charter, serious counterframe, material scales, evidence/error check, synthesis/reopening |
| Standard | Material work across methods, groups or scales | Protected frames/passes, explicit bridges/crosswalks, dependencies and structured synthesis |
| Deep | High stakes, systemic reach, conflict, novelty or irreversibility | Stronger affected-party coverage, differentiated inquiry, appropriate independent audit and declared coverage criteria |

Select depth from consequence, uncertainty, reversibility, novelty, disagreement, evidence and cost. Proportionality changes instrument weight and scope, not the correctness, accessibility, safety or honesty owed to an actual activity. More agents and reports do not independently strengthen a claim.

### 3.1 A usable inquiry contract

The tuition protocol's compact charter retains these fields; blanks are visible work, not fictitious agreement:

```yaml
inquiry_id: ""
inquiry_revision: 1
basis_ids: []
scale_regions: []
method_pass_ids: []
domain_profiles: []
purpose: ""
intended_impact: ""
question: ""
claim_types: []
decision_owner: ""
affected_parties: []
authority: { investigate: true, decide: false, act: false }
scope: { in: [], out: [], constraints: [] }
assumptions: []
uncertainties: []
evidence_budget: ""
action_budget: ""
stopping_conditions: []
defeaters: []
reopening_conditions: []
```

Also record exact inputs, versions, producing process/context and validity domain: people, subjects, phases, jurisdictions, systems and horizons. The example authority values are template defaults to replace with actual authority, not a limitation on work the user has already authorised.

Type a mixed claim before choosing its warrant: empirical/descriptive(measurement/sampling), predictive(out-of-sample calibration), causal(counterfactual identification), formal(definitions/derivation), interpretive(source fit/counter-reading), normative(values/rights/distribution), design/engineering(fitness/verification/failure), or exploratory(discovery and follow-up). Keep decisions as separate authorised choices. No amount of formal validity turns assisted accuracy into understanding or conformance into actual access.

A Frame Card records basis ID, focal question, constructs/exclusions, entities/relations, unit/horizon, standpoint, causal or interpretive account, evidence/methods, enabled actions, blind spots, failures and discriminating observations. A new frame earns its place by changing one of those materially. Protect at least one serious counterframe beyond screening, steelman it and let it change the preferred account. Common vocabulary is not mandatory when translation loses meaning.

Scale is a vector: temporal extent/resolution, population/aggregation, subject/phase/sequence, technical/organisational scope, jurisdiction/delivery, and causal/intervention/consequence/monitoring horizons. Separate the scale of observation from mechanism and consequence. Every cross-scale Bridge Claim records source/target scales, relation(`aggregation`, `mechanism`, `feedback`, `extrapolation`, `translation` in this protocol), assumptions, supporting/challenging evidence, loss/uncertainty, validity and failure. Every inter-frame Crosswalk Claim adds direction/cardinality, mapped and unmatched constructs and preserved/lost meaning. A partial, asymmetric or unavailable map is an acceptable result.

For each method pass record ID, basis, scale region, profiles, inputs, procedure, output, warrant, characteristic errors, constraints, success/failure/abort and dependencies. Preserve shared datasets, prompts, models, sources, analysts, instruments and institutions. Protected parallel work reduces some anchoring; it does not make these dependencies disappear.

### 3.2 Synthesis, decisions and learning from outcomes

Connect evidence to claims as supporting, challenging, qualifying, contextualising or non-discriminating. Distinguish contradiction under the same scope from different populations/horizons, operationalisation mismatch, method sensitivity, dependency, values, implementation/measurement failure, warranted translation or genuine incomparability. Resolve only by correcting an error, narrowing scope, conditioning a claim, applying a supported bridge/crosswalk, separating fact/value or collecting discriminating evidence. “Both contribute” is not itself a resolution.

Keep evidence, inference, values, rights, constraints, capability, authority and action in separate decision lanes. Compare credible alternatives: direct simpler action, existing tool/service, different technical mechanism, staged or reversible probe, deferral for discriminating evidence, and no action where it is actually a live choice. In this project the build commitment is settled, so an alternative must be framed at the particular intervention or sequence being decided. Apply non-compensatory rights/access/safety conditions before trade-offs; expose burden, distribution, reversibility and the strongest contrary case.

A Decision Record should make its identity/revision/date and intended reliance, question/scope/scales, owner/authority, affected parties, options, evidence/interpretation/limits, values/rights/constraints, theory of change, Bridge/Crosswalk Claims and sensitivities, expected benefits/harms and distribution, trade-offs, selected/deferred/rejected alternatives, dissent, rationale, residual uncertainty, operating preconditions, authorised next step, rollback and linked World-Return Contract explicit. A validated recommendation means it passed declared decision checks; it does not make the evidence certain or authorise implementation.

An audit identifies the exact claim, criterion, support or absence, discrepancy, consequence, severity, confidence, cheapest resolving action, affected scales/bases and finding status (`open`, `accepted-risk`, `resolved`, `disputed`). It ends `pass`, `qualified`, `reopen`, `block` or `inconclusive` with inspected scope and limits. Its independence class is explicit: **independent** requires materially separate people/bodies, incentives, context and judgement with competence/access; **protected-but-correlated** retains material shared sources, assumptions, organisation or accountability; **same-context self-review** uses the author/orchestrator or closely shared context. Source-based reviewer agreement is not independent empirical or professional assurance. An audit challenges its target; corrections should be separately attributable.

A World-Return Contract binds a material method/governance change to a concrete later action: changed mechanism, object-level prediction, baseline/comparator, validity domain, observations/instrument, threshold and horizon, owner, confounders/risks, stop/rollback and review. Observe whether the mechanism fired, detected the intended problem and changed behaviour; these are separate outcomes. Evaluate later benefit rather than declaring a new rule successful because it was written. The controlled service-learning path and experiment details are in 04; learner interaction can use only pre-authorised moves and bounded states.

Preserve epistemic status separately from lifecycle and permission. The tuition protocol uses `validated`, `provisional`, `inconclusive`, `insufficient-evidence`, `declined`, `reopened`, `superseded`, always scoped to explicit criteria. Lifecycle can be draft/ready/running/paused/completed/blocked/cancelled. A completed experiment may be inconclusive; a provisional design may be ready for a particular authorised test. A validation label never appoints an owner or authorises deployment.

### 3.3 Knowledge that should survive the session

Distinguish source, selected evidence, claim, interpretation, decision, policy/requirement and learning signal. Preserve stable identity, revision, producer, date, status and exact input versions. Material reinterpretation is a new revision with its parents; correction, retraction and supersession are events. Count independent evidence streams, not repeated reports. Keep observations distinct from learner-state estimates, policy from delivered action and session results from later unaided outcomes.

Capture → distil → graduate → enforce is a governed learning path. Capture expected versus observed with context, evidence, dependence, severity, alternatives and expiry. Distil across cases, including framing, measurement, routing, execution and governance failures. Graduate only a sufficiently stable/general lesson into the smallest proposed change with baseline, held-out/regression checks, risks, reviewers, authority, monitoring and rollback. Enforce after a versioned decision; observe outcomes and retain the previous version. A surprising interaction or generated suggestion is not permission to rewrite global prompts, state semantics, rewards or safeguards.

Preserve negative knowledge accurately: inaccessible is not nonexistent; unobserved is not a measured null; rejected is not falsified; expired is not wrong; absence of evidence is not evidence of absence. Keep current task state small—goal, scope, sources, revisions, completion, blockers, owners and next actions. Durable knowledge should earn its future usefulness. Personal learner data and speculative impressions do not belong in general project memory. Apply purpose/retention/access controls and preserve transformations so an anonymised or summarised carrier is not mistaken for raw evidence.

One canonical home per purpose should point to related material. A successor records whether it corrects, narrows, extends or reformats a predecessor; exact duplicates keep distinct occurrence provenance without multiplying evidence. The current reconstruction preserves useful meaning within this collection; earlier archive-all packaging rules remain history. A handoff must carry substantive definitions, rationale, evidence and contrary cases, not merely links to the source corpus. These protocols inform the work without overruling the user's latest reconstruction brief.

## 5. Recent plan-only opportunities and their operating limits

The EEF projection plan proposes31 Markdown files—30 strands plus a reference file—with exact fields, caveats, provenance and version identity. It changes projection, not acquisition, underlying data or serving. A useful experiment is whether an actual consumer can use the rendered corpus faithfully. The plan's existence does not establish a working renderer.

The visitor plan allows a gitignored `/visitors` checkout hosted under OCE while retaining its own `.git`, remotes, history and gates. Host ignore plus formatter/Markdown-ignore rules are needed; `.git/info/exclude` alone is insufficient. A vocabulary walker must skip nested `.git`. Commands require explicit visitor working directory and scope; `PRACTICE_COORDINATION_HOME` points to the host root and the host agent-tools binary can operate in visitor context, whereas a root `pnpm` command acts on the host. A bot-created repository may need its default branch seeded through the hosting API before a PR; verify remote commit identity when the bot push has no upstream. These are the recorded plan's operational details, not actions performed by this reconstruction. They provide a route for development without relocating the research collection or confusing host and visitor authority.

### 7.10 Interoperability contract for any epistemic module

Every method, model, human team or artificial-agent module should expose:

- intended function;
- inputs and evidence used;
- assumptions and dependencies;
- frame, scale and scope;
- operations or protocol;
- outputs and uncertainty;
- applicability limits;
- known failure modes;
- possible defeaters;
- provenance, authorship and version;
- what another module may and may not infer from its output.

Private chain-of-thought is neither required nor an adequate provenance mechanism. For AI-supported work, preserve task specifications, supplied evidence, model and tool versions, observable outputs and testable rationales.

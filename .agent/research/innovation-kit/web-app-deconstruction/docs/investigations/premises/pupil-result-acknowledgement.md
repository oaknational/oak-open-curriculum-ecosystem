# Pupil result transition and acknowledgement

## Decision boundary

This record asks what the authoritative pupil-learning transition is, when it is accepted, and how review, printable, shared and Classroom representations relate to it. It tests, but does not assume, that one authoritative result transition should precede every projection and acknowledgement.

The desired result may not be durable storage. Ordinary ephemeral progress, a pupil's private review, a teacher-shareable result and provider progress may be legitimately different outcomes. The system must establish that difference rather than inherit it from current routes and stores.

## Current observation

- **Literal behaviour:** one pupil lesson session resolves available activities, captures quiz/video/resource evidence, derives completion and renders review. It then supports a browser-local printable result, a remotely shared result and Google Classroom progress/result representations.
- **Inputs and outputs:** curriculum activity definitions, entry/share policy, pupil answers and media/resource actions enter session state; outputs include immediate feedback, completion, review, local attempt snapshots, share URLs and provider progress.
- **State and authority:** module-level lesson state becomes the review source; quiz state is copied into it; local storage owns printable snapshots; Firestore owns copied shared attempts; Google Classroom owns provider progress while OWA maps and writes session changes.
- **Dependencies and lifecycle:** route navigation, browser memory/local storage, clipboard, an API route, Firestore, Classroom APIs/cookies and curriculum content participate. Ordinary progress survives client navigation but not a hard refresh; completed local attempts have a different lifetime.
- **Excellence currently delivered:** account-free pupil learning, activity selection and restrictions, immediate grading/feedback, media alternatives, transcript/sign-language evidence, review, printable results, share and Classroom adaptation through a common result view.
- **Difficult states and exceptions:** restricted activity sets, incomplete sessions, read-only returned/turned-in Classroom work, hard refresh, duplicate/reordered writes, network failure, clipboard permission, expired/missing result, source curriculum change, privacy/retention and a provider state changing concurrently.
- **Known failures or duplication:** copy writes the URL before remote persistence is acknowledged; a Firestore exception can be represented as HTTP success; Classroom writes have no visible acknowledgement, retry, ordering or conflict state and errors are swallowed; three persistence paths adapt to one rendered result shape.
- **Historical reason or constraint:** ordinary, share and Classroom paths have different providers and product histories. Their current stores, routes and acknowledgement timing do not establish the enduring domain boundary.

Primary local evidence: [pupil lesson to results](../../current-state/journeys/pupil-lesson-to-results.md), [Classroom assignment to submission](../../current-state/journeys/classroom-assignment-to-submission.md), [freshness and failure](../../current-state/freshness-and-failure.md), and validation findings [V001-V003](../validation-register.md).

## Complexity classification

- **Essential domain complexity:** available activity policy, evidence and grading, completion, feedback, result meaning, read-only states, teacher/pupil audience and whether a result is snapshot or live progress.
- **Trust or policy obligation:** pupil privacy, safeguarding, authorization, retention/deletion, truthful acknowledgement, accessibility, data minimisation and curriculum attribution/licence.
- **Chosen system complexity:** module-level Zustand stores, separate quiz/lesson stores, route-driven effects, nanoid creation in the browser, local-storage keys, Firestore append and Classroom change subscriptions.
- **Accidental or migration complexity:** placeholder browse result route, canonical result URL collapse, error-masking mocks, mixed App/Pages routes and potentially duplicated projection shapes.
- **Compensating mechanism:** copying quiz state into lesson state, swallowing Classroom errors so learning can continue, local snapshots for printable results and early clipboard write may compensate for missing transition/acknowledgement semantics.
- **Unknown:** primary purpose of each result, intended ordinary persistence, retention/deletion rules, required Classroom consistency, whether completion is mutable and what success copy promises.

## Challenge the system

- Could review be rendered directly from a session snapshot without persisting any result?
- Could a teacher receive evidence through an existing Classroom or school system, removing public share URLs?
- Could a privacy-preserving, device-local session support explicit resume and expiry rather than accidental in-memory lifetime?
- Could the result be a content-addressed, signed artifact instead of a database document and route pair?
- Could one accepted command return the URL only after the remote representation is resolvable?
- Could Classroom synchronize only meaningful accepted outcomes instead of every intermediate store change?
- Could a provider adapter request effects from a deterministic session reducer and acknowledge them independently?
- Could product copy distinguish “copied”, “saved”, “shared” and “seen by teacher” so the technical system need not pretend they are one success?
- Is durable result storage needed at all for the educational outcome, or only because the current sharing journey assumes a URL?

## Excellence contract

- **Correctness and semantic integrity:** grading, availability and completion follow explicit curriculum/pedagogical rules; every result names lesson identity, source version, session context and evidence version; accepted results cannot silently change.
- **Curriculum and content integrity:** questions, answers, feedback, media/resource evidence, attribution and licence remain tied to the correct curriculum version; later content change has an intentional rendering policy.
- **Educational effectiveness:** feedback is timely, comprehensible and pedagogically appropriate; result representation supports pupil reflection and the teacher purpose it claims to serve rather than merely persisting data.
- **Accessibility and inclusive interaction:** every transition and failure is keyboard/screen-reader usable; feedback is announced without stealing context; print/share views preserve structure, MathJax alternatives and readable content.
- **Safeguarding, privacy, consent, rights and security:** collect the least pupil data; public identifiers are unguessable but not treated as authorization when the data requires access control; retention, revocation and deletion are defined; Classroom identity cannot leak into ordinary results.
- **Identity, state and effect semantics:** session, evidence, result, projection and acknowledgement have one named authority each; IDs, clocks and effects are explicit; duplicate, delayed, reordered and concurrent operations have specified outcomes.
- **Failure acknowledgement and recovery:** “copied”, “saved”, “published”, “synchronized” and “seen” are not conflated; recoverable failure preserves learning; terminal failure is visible and actionable; retry never creates contradictory attempts.
- **Reliability and operability:** state transitions and external effects are traceable without exposing pupil content; alerts distinguish acceptance failure, projection lag, provider rejection and rendering failure; repair does not require editing opaque stores.
- **Evolvability and conceptual coherence:** provider types stop at semantic boundaries; new projections do not change the session invariant; schema evolution and historic rendering have deliberate policies.
- **Idiomatic language, platform, protocol and framework use:** transaction/idempotency and HTTP status semantics are correct; browser clipboard/storage capabilities are acknowledged directly; custom workflow infrastructure exists only for meaningful states.
- **Developer, API and documentation experience:** commands and results make acknowledgement guarantees explicit in types and names; test fixtures cover adverse orderings; adapter contracts document provider authority, retention and retry.
- **Determinism, reproducibility, testability and diagnostics:** pure grading/projection is reproducible from pinned inputs; transition tests enumerate legal states; recorded effects can replay; diagnostics name session/result/projection without logging protected content.
- **Automated and human evidence required:** property/transition tests, real route/provider contract tests, concurrency and failure injection, accessibility testing, privacy/security review, curriculum/pedagogy review and pupil/teacher comprehension research.

## Conclusion

- **Outcome and obligations retained:** accurate pupil feedback and trustworthy, privacy-conscious learning evidence with truthful acknowledgement and recovery.
- **Premises accepted:** none yet; current evidence establishes one session-like core and three result paths but not whether their acceptance semantics should be one.
- **Premises rejected:** none yet.
- **Essential complexity:** pedagogical evidence/completion, audience and purpose of results, privacy/retention, authorization, external provider authority and acknowledgement guarantees.
- **Mechanisms removed or combined:** no decision earned. Stores, routes, local snapshots, Firestore sharing and Classroom synchronization remain challengeable.
- **Selected system shape:** unresolved among corrected distinct paths, one session aggregate, separate outcome commands, local-only results, server transactions, durable retry/events, provider authority or redesigned teacher evidence.
- **Remaining unknowns:** user intent, ordinary persistence, retention, result mutability, Classroom consistency, share authorization and precise success language.
- **Evidence that would reopen the decision:** new pedagogical or safeguarding evidence, provider contract change, result integrity incident, user misunderstanding, retention requirement or proof that the chosen acknowledgement can still expose an unavailable or contradictory result.

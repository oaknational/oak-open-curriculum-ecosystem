# Database, API and OCE concept lens portfolio

## Purpose

This is the control record for 59 differentiated attempts to understand the
Database-Tools to oak-openapi to OCE authority chain. The repository, semantic,
runtime and operations records follow mechanisms and boundaries. This portfolio
changes the primary question: it treats the same evidence as a human service,
curriculum knowledge system, temporal model, public API product, trust boundary,
control system, evolving institution and ecosystem kit.

The work uses OCE's pinned
[`concept-exploration`](https://github.com/oaknational/oak-open-curriculum-ecosystem/blob/bd878a3a550c8e5e5d21163a6d0962cebdaf43fa/.agent/skills/concept-exploration/SKILL-CANONICAL.md)
Practice. Every lens must complete:

1. reflection on literal observations and inherited assumptions;
2. a mechanism-neutral problem frame;
3. reopened competing explanations and solution shapes; and
4. warranted synthesis with explicit falsifiers and unresolved evidence.

This is current-state research for OCE and the Oak Innovation Kit. It is not a
remediation plan for Database-Tools or oak-openapi, and no mechanism survives
because it already exists.

## Orthogonality and collapse rule

Two terms from different disciplines are not two lenses by default. A pass
survives only when it changes at least one of:

- the person, claim, capability or institution being protected;
- the unit of analysis;
- the failure signal;
- the time horizon;
- the authority competent to decide; or
- the evidence which could falsify its synthesis.

Passes are classified during synthesis as:

- **orthogonal expansion** when they change the protected subject, unit or
  failure;
- **recursive deepening** when they make an existing seam more discriminating;
  or
- **triangulation** when an independent frame reaches a compatible finding.

Named patterns, technologies and methods are solution vocabulary, not lenses,
unless they pass this test. Repeated findings will be consolidated without
pretending that repeated wording is independent evidence.

## Required output per lens

Every pass must contain the exact ordered Movement 1-4 headings plus:

- a mechanism-neutral `Problem frame`;
- at least one explicit `Changed assumption`;
- warranted next investigation or proposal rows;
- a `Warrant` for each row;
- an `Explicit falsifier` for each row; and
- an `Unresolved evidence` section.

Observations link to immutable source lines. Inferences name their warrant.
Propositions remain falsifiable. Source existence is never outcome evidence.

## Cross-cutting questions

Each pass must eventually inform, reject or leave open these synthesis questions:

1. What value or obligation is genuinely independent of current mechanisms?
2. Where is competent semantic, operational and institutional authority?
3. Which identities, transitions, clocks and failure states must remain distinct?
4. Which mechanism is compensating for another avoidable system choice?
5. Which several systems disappear if a premise, workflow or authority changes?
6. What should the OCE kit encode once so additional consumers do not reproduce
   subtle failure?
7. What should remain a consumer/product decision rather than framework policy?
8. What evidence would make the proposed basis false?

## Research journal

### 2026-07-19: portfolio opened

**Observed:** The initial register contains 59 questions across human value,
semantics, time, contracts, trust, operations, assurance, evolution,
institutions and premise challenge. It includes database/API-specific lenses
which the earlier OWA portfolio did not need, such as projection freshness,
query amplification, online/bulk consistency and OpenAPI-to-OCE generation.

**Changed assumption:** A database architecture review is not sufficient. A
locally coherent schema can still encode an invalid educational claim, hide work
from editors, expose rights-restricted content, create an unusable public
contract, provide false operational acknowledgement or externalise complexity to
every ecosystem consumer.

**Unknown:** Which passes will remain independently useful after full evidence
and adversarial collapse. The register is a commitment to ask, not to preserve 59
subsystems or conclusions.

### 2026-07-19: all 59 passes synthesised

**Observed:** Every fixed lens completed the four Concept Explorer movements and
the six end-to-end journeys tested whether the distinctions compose. Independent
families repeatedly exposed plural authority, hidden identity/clocks, missing
release completeness, overstated acknowledgements, transformation loss and
compensating policy.

**Changed assumption:** The smallest useful basis is not a list of current layers
or one noun per implementation. Stable entities, revisions and placements remain
separate; publication/projection/contract releases share a typed protocol but not
an authority or clock; capability contracts remain separate from policy
decisions; commands, outcomes and optional operations remain separate; resource
descriptors remain separate from delivery grants and bytes.

**Unknown:** Whether this candidate basis remains sufficient, comprehensible and
operationally fit when tested against authoritative curriculum/rights ownership,
production workloads, incidents, representative human use and an independent
consumer built without source-repository archaeology.

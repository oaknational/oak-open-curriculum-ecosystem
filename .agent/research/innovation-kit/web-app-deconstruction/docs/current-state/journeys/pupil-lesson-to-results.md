# Pupil lesson to results

## Scope and outcome

This trace follows a pupil from lesson entry through overview, introduction, starter quiz, video, exit quiz, review, and the local, shared, or Classroom result representations. It covers canonical, curriculum-browse, teacher-shared, and Google Classroom entry variants. Teacher assignment creation and curriculum browsing before lesson selection are included only where they change the lesson contract.

The evidence is pinned to OWA commit [`510ac63a62fb37a70183b00ce0f5fb15be4491e5`](https://github.com/oaknational/Oak-Web-Application/tree/510ac63a62fb37a70183b00ce0f5fb15be4491e5).

**Observed:** The pupil outcome is not a strictly linear wizard. It is a hub-and-spoke activity session: overview recommends the first incomplete activity, all available activities can initially be selected, most completed activities return to overview, and review becomes available when the configured activity set is complete. Completed quizzes are locked while intro and video can be revisited ([overview orchestration](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilOverviewExperience.ts#L95-L143), [section item policy](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Overview/buildOverviewSectionItems.ts#L34-L84)).

**Inferred:** The enduring capability is a `PupilLessonSession`, not six pages. Its contract is: resolve an available activity set, collect section evidence, derive completion, preserve or restore progress under a named persistence policy, and project that evidence into review and result views. Routes, entry context, persistence provider, and result publication are adapters around that contract.

**Unknown:** Product intent has not yet established whether anonymous progress is deliberately tab-lifetime only, whether every activity must remain independently selectable, or whether the final result is primarily pupil feedback, teacher evidence, or both.

### Candidate capability model and falsifiers

**Candidate model:** One provider-independent lesson-session model can serve canonical, browse, restricted-share, and Classroom journeys if entry policy, progress persistence, identity, analytics, and result publication are explicit ports. This is a concrete test of [H001](../../hypotheses/H001-capability-owned-modules.md) and [H004](../../hypotheses/H004-domain-ports-and-freshness.md), not a separate registered architecture hypothesis.

Reject or narrow this candidate model if runtime or change-history evidence shows any of the following:

- **Invalidator:** Shared variants require materially different activity semantics, not merely a restricted activity set and navigation policy.
- **Invalidator:** Classroom resume, submission, and read-only rules cannot be represented without leaking Google identifiers and provider states through the core lesson model.
- **Invalidator:** Extracting the session duplicates more curriculum validation, quiz grading, media, download, or analytics behavior than it clarifies.
- **Invalidator:** A fixture-backed vertical slice needs Next router state to express ordinary section completion or cannot substitute local and Classroom progress providers behind the same contract.
- **Invalidator:** User research establishes that local review, copied results, and Classroom results are different outcomes that should not share one result projection.

### Activity sequence

1. **Observed:** `overview` shows lesson identity, outcomes, content guidance, takedown/expiry information, the available activity set, and progress. Its primary action selects the first incomplete section in the order `intro`, `starter-quiz`, `video`, `exit-quiz`; if none remain it opens `review` ([section model](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/lessonSections.ts#L3-L20), [next-incomplete rule](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Shared/pickNextIncompleteSection.ts#L7-L18)).
2. **Observed:** `intro` presents readiness, equipment, additional files, content guidance, supervision, worksheet metadata, and licence. Proceed marks intro complete, then returns to overview unless that completed the configured lesson ([intro view composition](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/PageContent/IntroPageContent.tsx#L56-L179), [intro transition](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilIntroExperience.ts#L104-L136)).
3. **Observed:** `starter-quiz` and `exit-quiz` initialise a separate quiz store from curriculum questions and any saved per-question results. Each submitted answer is graded, persisted into lesson progress, and followed by immediate feedback; completing the quiz returns to overview or, if all configured sections are complete, review ([quiz hydration and persistence](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages-helpers/pupil/lessons-pages/new/QuizPageContent.tsx#L134-L221), [quiz completion](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages-helpers/pupil/lessons-pages/new/QuizPageContent.tsx#L266-L320)).
4. **Observed:** `video` uses a signed Mux playback ID, resumes from stored elapsed time, offers transcript and sign-language video when present, records media/accessibility interactions, and lets the pupil explicitly mark the video finished. The explicit action, not the 90-percent heuristic, controls section completion ([video data and event handling](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilVideoExperience.ts#L95-L175), [video completion](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilVideoExperience.ts#L199-L234)).
5. **Observed:** `review` renders completion for intro/video, marks and expands quiz results, derives a final encouragement, and exposes share/print controls only outside Classroom. An incomplete non-read-only session is redirected to overview; a read-only Classroom session can review prior work ([review state and guard](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilReviewExperience.ts#L66-L90), [review effects](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilReviewExperience.ts#L143-L191)).

**Inferred:** The ordered path is a default teaching sequence, not a domain invariant. Any replacement that encodes it as a mandatory stepper would change current behavior.

## End-to-end data and control flow

### 1. Resolve lesson content

**Observed:** Every Pages section repeats a small route adapter that adds its section name and delegates to one `getProps` function. That function selects preview, canonical, or browse curriculum queries; applies redirect/not-found behavior; verifies section availability; and builds a common prop shape ([route adapter example](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages/pupils/lessons/%5BlessonSlug%5D/video.tsx#L17-L37), [query selection](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages-helpers/pupil/lessons-pages/getProps.ts#L35-L119)).

**Observed:** The curriculum adapter validates upstream GraphQL data with Zod, applies Oak overrides/exceptions, reshapes snake case to camel case, and reports uniqueness violations before returning lesson content and browse data ([pupil lesson query](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/node-lib/curriculum-api-2023/queries/pupilLesson/pupilLesson.query.ts#L52-L135)).

**Observed:** Prop construction also resolves transcripts, fetching and parsing a captions file when transcript sentences are absent. Production lesson routes propagate this resource failure; preview routes deliberately degrade to an empty transcript ([resource hydration](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages-helpers/pupil/lessons-pages/pupilLessonPage.helpers.ts#L32-L94), [caption fallback](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/pupilUtils/requestLessonResources.ts#L19-L38)).

**Observed:** Dynamic lesson pages use blocking fallback and inherit the generic `getPageProps` ISR decorator. That decorator uses a configuration value named `sanityRevalidateSeconds`, even for curriculum lesson content ([blocking paths](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages-helpers/get-static-paths.ts#L10-L21), [ISR decorator](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/node-lib/isr/index.ts#L23-L32)).

### 2. Initialise the lesson session

**Observed:** `PupilLayout` is a focused, full-height shell without normal site chrome. It installs an iframe media guard, initialises lesson stores, adds Classroom analytics and a read-only banner, and delegates common theme, consent, analytics, error, overlay, and pupil-client behavior to the Pages root ([pupil layout](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/PupilLayout/PupilLayout.tsx#L28-L51), [Pages root](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages/_app.tsx#L47-L90)).

**Observed:** `usePupilStores` derives the available activity list from content and share variant, waits for Classroom resolution, initialises progress, builds the analytics context, and subscribes Classroom write-back. The progress store is module-level Zustand with no persistence middleware ([store orchestration](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Shared/usePupilStores.ts#L32-L81), [analytics and sync](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Shared/usePupilStores.ts#L103-L153), [Zustand store](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/context/PupilLessonProgress/usePupilLessonProgress.ts#L13-L70)).

**Observed:** A new lesson slug resets and seeds progress; the same slug preserves existing section results. Session identity does not include route variant, programme/unit, Classroom assignment, or pupil identity ([initialisation action](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/context/PupilLessonProgress/pupilLessonProgressStateActions.ts#L25-L54)).

**Inferred:** Client navigation between contexts for the same lesson can retain the wrong allowed-section or progress policy because `usePupilStores` exits when the current lesson slug matches before considering the variant or Classroom context. This needs a runtime reproduction before being recorded as a defect.

### 3. Capture section evidence

**Observed:** The progress model records quiz grade, question count and answer-level results; video playback, elapsed time, mute, sign-language and transcript use; intro worksheet/file state; per-section completion; and derived lesson started/completed flags ([progress types](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/context/PupilLessonProgress/pupilLessonProgressTypes.ts#L12-L74)).

**Observed:** Quiz grading is application-owned for multiple-choice, short-answer, order, and match questions. Question state includes answer, correct answer, feedback, partial correctness, hint use, and mode; every graded answer is copied into the progress store ([grading functions](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Quiz/gradeQuizQuestion.ts#L29-L128), [persisted quiz result](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/context/PupilLessonQuiz/pupilLessonQuizHelpers.ts#L140-L158)).

**Observed:** Video time is copied to progress for non-playing events or after more than ten seconds of additional playback. This supports resume without writing on every playing event ([video persistence rule](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Video/shouldPersistVideoTimeElapsed.ts#L3-L17)).

**Observed:** Worksheet and additional-file flags are updated before the asynchronous download outcome is known. Worksheet analytics only fires on success, but the review progress flag remains `downloaded` after a failed request; additional-file state is likewise set before its failure alert ([intro download handlers](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilIntroExperience.ts#L150-L170), [worksheet failure](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Intro/useWorksheetDownload.ts#L21-L40)).

1. **Observed, local printable:** Once an ordinary lesson is complete, review builds an attempt snapshot, generates a nanoid, and stores `oak-pupil-lesson-attempt:<attemptId>` in local storage. The printable URL reads only that browser-local record and combines it with statically resolved curriculum content ([review local snapshot](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilReviewExperience.ts#L143-L167), [client storage](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/browser-lib/pupil-client/client.ts#L110-L132), [printable reader](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages/pupils/lessons/%5BlessonSlug%5D/results/%5BattemptId%5D/printable.tsx#L35-L89)).
2. **Observed, copied share:** Copy link creates a separate attempt ID, immediately writes a canonical share URL to the clipboard, and asynchronously posts a Zod-projected attempt to `/api/pupil/lesson-attempt`. The server checks uniqueness and appends a Firestore document; the share page server-renders curriculum content plus the attempt selected by ID ([copy flow](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/Hooks/usePupilReviewExperience.ts#L99-L138), [attempt API](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/app/api/pupil/lesson-attempt/route.ts#L33-L69), [Firestore write](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/node-lib/pupil-api/lesson-attempt/logLessonAttempt.ts#L8-L16), [share page](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages/pupils/lessons/%5BlessonSlug%5D/results/%5BattemptId%5D/share.tsx#L40-L81)).
3. **Observed, Classroom progress:** Classroom hydrates provider progress into the session model and subscribes to every `sectionResults` change. ## Cross-cutting concerns

### State and persistence

- **Observed:** Ordinary in-progress progress survives client-side section navigation because the Zustand stores are module-level, but there is no local/session persistence middleware. A hard refresh starts an ordinary lesson again; only a completed review creates a local printable snapshot.
- **Observed:** The lesson store and quiz store are separate. Quiz state is copied into lesson state after each graded answer, making the lesson store the review/persistence source of truth ([quiz-to-lesson copy](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/pages-helpers/pupil/lessons-pages/new/QuizPageContent.tsx#L206-L230)).
- **Observed:** Classroom write-back has no visible debounce, sequencing, acknowledgement state, retry queue, or conflict/version field. Errors are swallowed so the lesson can continue ([sync behavior](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/components/PupilComponents/Views/ViewHelpers/Shared/useClassroomProgressSync.ts#L56-L69)).
- **Inferred:** Concurrent Classroom writes can arrive out of order, and a silent last-write failure can leave provider progress behind the UI. This needs a latency/failure test against the real adapter.
- **Unknown:** Retention, expiry, deletion, and revocation policy for local and Firestore attempts is not expressed in the inspected journey code.

### Identity and privacy

- **Observed:** Ordinary lesson completion does not require a pupil account. The attempt payload contains lesson, subject/year, and answer/progress evidence but no Oak user ID ([attempt schema](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/node-lib/pupil-api/types/lessonAttempt.ts#L81-L147)).
- **Observed:** The pupil attempt GET/POST handlers show no identity or authorization check. Possession of a nanoid is the visible access mechanism for a shared result ([attempt GET/POST](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/app/api/pupil/lesson-attempt/route.ts#L10-L69)).
- **Observed:** Classroom identity uses separate pupil and teacher access/session cookies plus course, item, attachment, submission, and login-hint context ([Classroom auth headers](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/browser-lib/google-classroom/googleClassroomApi.ts#L12-L33), [assignment context](https://github.com/oaknational/Oak-Web-Application/blob/510ac63a62fb37a70183b00ce0f5fb15be4491e5/src/browser-lib/google-classroom/classroomAssignmentContext.ts#L3-L28)).

## Observed strengths and preservation questions

These mechanisms are visible in source. Their impact and necessity remain preservation hypotheses until product, pupil, teacher, operational or impact evidence establishes them.

- **Observed:** A pupil can start without an Oak account, choose activities from a clear overview, and see progress and immediate answer feedback.
- **Observed:** Lesson composition adapts to missing quiz/video data and to teacher-selected shared subsets without forking grading or review semantics.
- **Observed:** Content warnings, age restrictions, supervision, takedown/expiry rules, licence, attribution, and resource availability travel with the lesson rather than being optional editorial decoration.
- **Observed:** Runtime schema validation and explicit missing-content handling protect pupils from malformed or withdrawn curriculum data.
- **Observed:** Quiz behavior supports multiple question models, explanatory content, hints, partial correctness, code, maths, and rich answer media.
- **Observed:** Video resume evidence, transcripts and sign-language variants are part of the learning model and analytics, not bolt-on links.
- **Observed:** Classroom restores answer-level work, writes progress during the lesson, prevents edits after turn-in/return, and reuses the common review/result projection.
- **Observed:** Result sharing is pupil-controlled and does not require identifying the pupil in the stored attempt.
- **Observed:** Accessibility is addressed in semantic Oak Components, focus management, alternative media, explicit control labels, live announcements, reduced chrome, Storybook checks, and deployment Pa11y. These mechanisms need outcome-level verification, not removal.
- **Inferred:** Preserve the educational and safeguarding contracts, but do not preserve route duplication, source-shaped state, or accidental persistence semantics merely because they currently carry those contracts.

## Implications for current hypotheses

### [H001: Capability-owned modules](../../hypotheses/H001-capability-owned-modules.md)

**Supports:** The trace can be explained as one pupil-learning capability with explicit curriculum, media/download, attempt, Classroom, analytics, and navigation dependencies, but current files are distributed across technical and router taxonomies. Route files are already becoming thin adapters, and common page-content/hooks demonstrate that the same capability serves canonical, browse, preview, and some shared routes.

**Weakens:** Classroom identity/submission, generic curriculum query validation, downloads, and analytics are genuine cross-capability services. A single folder that absorbs their implementations would create a large audience silo rather than clear ownership.

**Discriminating next step:** Model `PupilLessonSession` as a vertical slice that owns activity policy and result projection but consumes explicit provider ports. Compare a change such as "retry failed Classroom progress without duplicate analytics" in that slice and in current OWA. Invalidate H001 for this journey if the slice introduces cycles or duplicates existing domain validation.

### [H003: Unified runtime-shell contract](../../hypotheses/H003-unified-runtime-shell.md)

**Supports:** One Classroom entry begins in the App Router, crosses into a Pages lesson that depends on Pages-root pupil/overlay/error/analytics providers, and later exposes a separate App Router teacher-authenticated result route. This is direct evidence for named shell outcomes across router implementations.

**Weakens:** The focused pupil shell intentionally omits normal chrome, and pupil Classroom entry, anonymous lesson runtime, and teacher result review require different identity/provider profiles. One unconditional provider tree would be the wrong interpretation.

**Discriminating next step:** Add shell profiles for anonymous pupil lesson, Classroom pupil lesson, and Classroom teacher results. Contract-test consent, pupil-client availability, error fallback, metadata/noindex, iframe guard, analytics context, and auth failure across both routers. Invalidate or narrow H003 if these are intentionally separate products with no meaningful shared outcomes or if conformance adds client code and hydration work without preserving a common obligation.

### [H004: Domain ports and explicit freshness](../../hypotheses/H004-domain-ports-and-freshness.md)

**Supports testing:** The outcome combines ISR curriculum content using a broadly named default, captions/media, live resource downloads, ephemeral browser state, append-only Firestore attempts in the inspected path, and mutable Classroom progress/submission state. Their freshness and degraded behavior are materially different, while current UI hooks coordinate several directly.

**Weakens:** `pupilLessonQuery` already performs valuable validation, exception handling, and domain shaping. Wrapping it in a pass-through `loadLesson` abstraction would add no value and could hide canonical/browse query needs.

**Discriminating next step:** Specify outcome-level ports and semantics for `loadLesson`, `loadProgress`, `saveProgress`, `publishResult`, `loadPublishedResult`, `downloadResource`, and `getSubmissionState`, including freshness, idempotency, ordering, retry, stale behavior, and user-visible failure. Invalidate H004 where a port has no independent policy and merely renames the existing adapter.

### [H005: Journey-level confidence](../../hypotheses/H005-journey-level-confidence.md)

**Supports a discriminating test:** This journey crosses permanent redirects, ISR data, module state, answer grading, media callbacks, clipboard, local storage, Firestore, two auth profiles, Classroom hydration/write-back, and three result routes. Current local tests cannot establish that the outcome works across those boundaries, but static composition does not establish that a journey test will have unique or decisive signal.

**Weakens:** Canonical, restricted-share, Classroom-resume, local-print, and remote-share paths have materially different contracts. A single happy-path browser test would create false confidence; external Classroom simulation could also stop predicting provider behavior.

**Discriminating next step:** Build a small parameterised journey suite with controlled curriculum, attempt, media, and Classroom adapters:

1. Complete an anonymous lesson, review answers, and render its local printable result.
2. Publish a result, wait for confirmed persistence, and open the copied URL; inject a save failure.
3. Prove a shared variant cannot enter or complete excluded activities, including same-lesson context changes.
4. Resume partial Classroom answers, observe ordered write-back, turn in, and prove the lesson becomes review-only.
5. Exercise content withdrawal, missing transcript, download failure, refresh, and zero-score feedback at the most direct evidence layer.

Invalidate or narrow H005 if these tests require production-only provider behavior that controlled adapters cannot represent, remain flaky after controlling identity/time/network, or provide less trustworthy or diagnostic evidence than focused integration tests.

## Disposition (follow-up — added 2026-06-23)

The two non-blocking findings above were addressed the same day by the
`mcp-self-description-fidelity` plan (WS1 + WS2). The run record above is left
exactly as observed at run time.

- **[P3] Broad-payload overflow** — WS1 added scope/page hints to the
  descriptions of the overflowing tools. `browse-curriculum` now names
  `subject`/`keyStage` narrowing; `search` names `size`/`from` paging;
  `get-sequences-assets` names `year`/`type`. `tools/list` over the local server
  now carries `large payload at broad scope` plus the real narrowing on each
  (proven by `mcp-app-pipeline.e2e.test.ts`). The descriptive hint is the cure;
  true server-side pagination is an explicit non-goal.
- **[Obs] Ontology subject drift (13 vs 17)** — WS2 made the
  get-curriculum-model ontology schema-derive its subject list from the
  generated `AllSubjectsResponseSchema`, so it exposes all 17 and cannot drift;
  the key-stage list and KS4 examSubject variants are likewise derived. Ontology
  version is now `0.2.0`, and the notice states which fields are derived vs
  authored.
